# 맵은 방 8개로 나누되 방 하나를 크게 만든다

## 문제

Phase 4에서 절차적 방 배치를 만들어야 하는데, 그 전에 맵의 단위를 정해야 했다.

개발자 취향은 코어 키퍼 같은 **넓은 단일 맵** 쪽이었다.
GDD 원안은 **방 프리팹 8개**를 절차적으로 잇는 구조다.

Phase 3까지는 이 결정과 무관해서 미뤄뒀고, Phase 4 착수 전에 정하기로 했다.

## 검토한 대안

**안 A: 방 8개 + 절차적 배치 (GDD 원안)**
- 장점: 20분 승패 구조가 명확하다. 가방 시너지가 짧은 런을 전제하므로 궁합이 맞다.
- 장점: **절차적 생성과 도달성 검증이 `feature-pool` 의 A급 항목**이고 EditMode
  테스트 대상이다.
- 단점: 개발자 취향과 다르다.

**안 B: 넓은 단일 맵**
- 장점: 취향에 맞다. 컬링과 청크 관리라는 다른 종류의 어필을 얻는다.
- 단점: 승패 구조가 흐려진다. GDD 가 정한 '20분짜리'와 충돌한다.
- 단점: **도형 프로토타입에서 텅 빈 공간이 된다.** 아래 참조.
- 단점: 컬링은 테스트가 어렵고 측정으로 증명해야 한다.

**안 C: 넓은 구역 2~3개 (절충)**
- 단점: **어느 쪽 어필도 얻지 못한다.** 구역이 두셋이면 배치할 것이 없어 절차적
  생성이 성립하지 않고, 컬링을 자랑할 만큼 넓지도 않다.

## 선택과 이유

**A를 골랐다. 다만 방 하나의 크기를 화면 두세 개 분량으로 키운다.**

### 결정적인 것은 취향도 어필도 아니었다

**도형 프로토타입에서 넓은 맵이 어떻게 보이는가**가 갈랐다.

GDD 아트 방침이 도형 프로토타입을 기본값으로 두고,
**에셋을 입히지 못해도 제출 가능한 상태를 항상 유지**하라고 요구한다.

코어 키퍼가 재미있는 이유는 타일 아트와 채집·건축이 넓은 공간을 채우기 때문이다.
**그것이 없으면 넓은 맵은 회색 벌판이다.** Phase 6에서 플레이 영상 앞 15초에
무엇을 넣을지 생각하면 분명해진다.

**B는 에셋 도입이 실패하면 같이 무너진다.** 아트 방침의 전제 자체를 어긴다.
방 단위는 사각형으로도 성립한다. 방마다 적 구성이 다르면 그것으로 구분된다.

### 방금 만든 자산이 A를 가리켰다

스탯 시스템에서 EditMode 테스트 22개와 순수한 `JM2D.Logic` 어셈블리가 생겼다.
**맵 생성 알고리즘은 MonoBehaviour 가 필요 없는 순수 로직**이라 그 위에 바로 올라간다.

B를 택하면 이 자산을 쓰지 못하고, 테스트가 어려운 영역으로 갈아타게 된다.

### 취향은 방 크기로 가져간다

**'방'이 좁아야 할 이유가 없다.** 화면 두세 개 분량으로 넓히면 탐험감이 생기고,
입구와 출구가 명확해 절차적 배치와 도달성 검증은 그대로 성립한다.

**하나의 큰 공간을 여덟으로 나눈 것**으로 보면 된다.
GDD 의 '방 프리팹 8개'와 '방 1개당 웨이브 2~3'도 그대로 유지된다.

### 일정이 전제를 바꾸지는 않았다

첫 커밋이 2026-08-28 이고 Phase 1~3 이 8일 만에 끝났다. 계획보다 6주 빠르다.
**넓은 맵을 반대하던 근거 중 '완성 확률'의 무게는 줄었다.**

그럼에도 A를 고른 것은 위의 두 이유 때문이다. **시간이 남아도 도형으로 채운
넓은 맵은 여전히 비어 보이고, 테스트 자산도 여전히 못 쓴다.**

## 결과

- Phase 4 의 절차적 방 배치를 원안대로 진행한다.
- 방 크기는 화면 두세 개 분량을 기준으로 잡는다. 정확한 수치는 실제로
  만들어 보고 정한다.
- 절차적 생성이 **EditMode 테스트의 두 번째 대상**이 된다.
  연결성과 방 개수 보장이 검증 항목이다.

## 한계 / 남은 문제

- **방 크기를 키우면 한 방의 적 수와 웨이브 구성을 다시 봐야 한다.**
  좁은 방 기준으로 잡은 '웨이브 2~3' 이 넓은 방에서는 허전할 수 있다.
  Phase 4 난이도 튜닝에서 함께 본다.
- **방이 커지면 카메라 처리를 정해야 한다.** 방 전체가 한 화면에 안 들어오므로
  플레이어를 따라가는 카메라가 필요하다. 지금은 고정이다.
- **컬링 어필을 포기했다.** 넓은 맵에서 얻을 수 있었던 최적화 이야기는
  이 결정으로 사라진다. 대신 절차적 생성과 도달성 검증을 가져간다.
- 이 결정은 **취향을 완전히 만족시키지 않는다.** 방 크기로 절반쯤 가져왔을 뿐이다.
