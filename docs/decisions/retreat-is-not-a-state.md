# 후퇴는 상태가 아니라 매 스텝 거리로 정하는 규칙이다

## 문제

근접 적과 돌진 적은 교전 중 상태마다 할 일이 하나였다. 공격 중에는 서서 때리고, 예고 중에는 서 있고, 돌진 중에는 달린다.

원거리 적은 **물러나면서 쏜다.** 이동(후퇴 · 정지)과 사격(조준 · 재장전)이 동시에 일어난다.
`enum` 하나로 짠 상태 머신에 이것을 어떻게 넣을지가 문제였다.

[FSM 구조 결정](enemy-fsm-structure.md)은 줄 수를 어림할 때 '원거리 적의 상태가 셋이다' 를 가정했다.
조준, 발사, 후퇴 같은 것을 떠올린 가정이었다.

## 검토한 대안

### 안 A: 후퇴를 상태 하나로 만든다
`State { Aim, Cooldown, Retreat }`

- 장점: 적 둘과 같은 모양이다. 상태마다 할 일이 하나다.
- 단점: **후퇴 중에는 조준도 재장전도 못 한다.** 명세의 '물러나면서 쏜다' 가 성립하지 않는다.
- 단점: 조준 타이머가 0.3초 남았을 때 후퇴로 가면, 남은 시간과 돌아갈 상태를 따로 기억해야 한다.

### 안 B: 조합을 모두 상태로 만든다
`AimStanding`, `AimRetreating`, `CooldownStanding`, `CooldownRetreating`

- 장점: 동시 행동을 정확히 표현한다.
- 단점: **상태 폭발이다.** 두 가지씩 둘이 넷이 되고, 동시 행동이 하나 더 오면(옆걸음 같은 것) 여섯, 여덟으로 는다.
- 단점: 조준에서 재장전으로 가는 전이를 서 있을 때와 물러날 때 두 번씩 써야 한다.

### 안 C: 상태 머신을 둘로 나눈다 (이동 FSM + 사격 FSM)
- 장점: 동시에 도는 관심사를 떼어 놓는 교과서적인 답이다.
- 단점: **이동에는 기억할 것이 없다.** 지금 거리만 보면 물러날지 설지 정해진다.
  상태 머신 틀을 하나 더 만들 이유가 없다.

### 안 D: 이동은 `switch` 밖에서 매 스텝 거리로 정하고, 사격만 상태로 둔다
- 장점: 사격 상태는 둘뿐이고, 이동은 `if` 하나다.
- 장점: 부모(`EnemyBase`)의 도구 `Move`, `Stop`, `DirectionToTarget` 으로 된다.
- 단점: 교전 중 할 일이 `switch` 한 곳에 모이지 않는다. `switch` 앞(이동)과 뒤(사격 멈춤)에도 코드가 있다.

## 선택과 이유

**D 를 골랐다.** 판단 기준은 이것이었다.

> **상태로 만들 것은 이전에 무슨 일이 있었는지 알아야 다음을 정할 수 있는 것뿐이다.**

조준은 '0.3초 남았다' 를 알아야 다음을 정한다. 기억이 필요하니 상태다.
후퇴는 지금 거리가 3 보다 가까운지만 보면 된다. 기억이 필요 없으니 상태가 아니다.
**기억이 필요 없는 것을 상태로 만들면 기억해야 할 것만 는다.** A 와 B 가 그렇게 됐다.

C 는 D 와 같은 생각을 더 큰 틀로 한 것이다. 이동에 기억이 필요해지는 날 C 로 간다.

## 결과

- `RangedEnemy` 는 **83줄이고 상태는 둘**(조준, 재장전)이다. FSM 구조 결정이 '상태 셋' 으로 어림한 78줄과 비슷하다.
  상태를 하나 덜 만든 대신 `switch` 밖의 이동과 사격 멈춤이 그만큼을 채웠다.
- **`EnemyBase` 는 한 줄도 고치지 않았다.** 교전 중 이동이 상태와 따로 도는 첫 적이었지만 부모의 도구로 충분했다.
- **타이머 네 줄(`TimeUp`)이 `DashEnemy` 와 겹친다. 부모로 올리지 않았다.**
  올리면 부모가 자식의 타이머를 알아야 해서 '부모는 할 일만 열고 필드는 열지 않는다' 는 경계가 흐려진다.
  네 줄을 아끼려고 그 경계를 흐리지 않았다. 셋째 반복이 오면 다시 본다.
- 후퇴 거리가 사격 시작 거리보다 좁지 않으면 `OnValidate` 가 경고한다. 후퇴가 사격 구간을 넘으면
  물러나기와 쫓기가 거리를 반대로 밀어 추적과 교전을 오간다.

## 한계 / 남은 문제

- **이동에 기억이 필요해지면 D 가 무너진다.** '한 번 물러나기 시작하면 1초는 계속 물러난다' 같은 규칙이 오면
  이동도 상태가 되어야 하고, 그때 C 로 간다.
- **`switch` 밖의 규칙은 색으로 드러나지 않는다.** 리뷰에서 잡은 버그 셋이 모두 `switch` 밖에 있었다.
  사격 멈춤의 `!` 누락, 후퇴 방향의 부호 누락, 그리고 `DirectionToTarget() * new Vector2(-1f, 0)` 이다.
  마지막은 `Vector2` 끼리 곱하면 성분끼리 곱해져 y 가 0 이 되는 버그라, **옆에서 다가가면 맞아 보이고
  위에서 다가가야 드러났다.** 상태는 색이 바뀌어 눈에 띄지만 규칙은 움직임을 보고 판단해야 해서,
  체크리스트에 '옆과 위아래 양쪽에서 다가간다' 를 넣었다.
- **후퇴가 여유 구간을 넘는 조합은 히스테리시스로 막지 못한다.** 데이터 경고로만 막는다.
  에셋 값을 잘못 넣으면 경고가 뜨지만 게임은 그대로 돈다.
