# 방은 Tilemap 프리팹 하나이고, 방 크기는 칠한 벽에서만 읽는다

## 문제

4-A 가 만든 좌표 여덟 개를 걸어 다닐 수 있는 방으로 바꿔야 했다. 정할 것은 넷이었다.

- 방을 무엇으로 만드나 (벽, 바닥, 문)
- 방 크기를 어디에 적나. 방을 놓는 코드, 카메라 경계, 방 찾기가 모두 이 값을 쓴다
- 문을 어떻게 열고 닫나. 4-C 에서 전투 중에 닫혀야 한다
- 넓은 방이 비어 보이면 장애물을 넣나

그때 씬의 방은 스프라이트를 늘린 좌우 벽 두 개였다.

## 검토한 대안

### 벽

| 안 | 판단 |
|---|---|
| 스프라이트 벽 조각 | 익숙하다. 문 자리마다 벽을 둘로 나눠 한 방에 조각이 여덟 개 이상 생긴다 |
| **Tilemap** | 이미 설치된 패키지다. 칸 단위로 칠하고 콜라이더를 하나로 합친다. 타일 한 칸이 곧 격자 한 칸이라 방 안 장애물과 BFS 로 이어진다 |

바닥은 사각형 하나라 Tilemap 없이 스프라이트 한 장을 늘렸다. 방 종류 색은 `SpriteRenderer.color` 하나로 바꾼다.

### 방 크기를 적는 곳

| 안 | 판단 |
|---|---|
| 코드에 상수 | 프리팹을 고치고 상수를 잊으면 방이 겹치거나 벌어지는데 오류가 없다 |
| 인스펙터 칸 | 같은 문제다. '계산에 쓰이는 값은 인스펙터에 맡기지 않는다' 는 규칙과도 어긋난다 |
| **벽 Tilemap 의 칠한 범위(`cellBounds`)** | 값이 칠한 타일 한 곳에만 있다 |

### 문

| 안 | 판단 |
|---|---|
| 타일을 코드로 칠했다 지우기 | 문 자리를 벽 Tilemap 과 섞어 다룬다 |
| **문 구멍마다 문 오브젝트 하나, 켜면 닫힘** | `SetActive` 한 줄이다. 4-C 에서 전투 중 닫는 문으로 그대로 쓴다 |

## 선택과 이유

**Tilemap 벽과 문 오브젝트 넷을 가진 방 프리팹 하나(`Room.prefab`). 방 크기는 `Room.Size` 가 벽의 `cellBounds` 에서 읽는다.**
32 와 18 은 코드 어디에도 없다. 방을 놓는 간격(`LevelBuilder`)과 카메라 경계(`Room.Awake`)가 모두 이 값을 받아, 벽을 다시 칠하면 셋이 함께 바뀐다.

**방 크기는 짝수다.** Tilemap 의 칸 (x, y) 는 x 에서 x+1 까지를 덮는다. 홀수 폭이면 방 중심이 반 칸 어긋나 Grid 를 반 칸 옮기는 요령이 필요하다.
짝수면 -16 부터 15 까지 칠해 -16 에서 16 까지 덮는다. 문도 짝수 폭(4)이라 가운데에 맞는다.
바깥 32 × 18 은 화면(약 17.8 × 10)의 1.7 × 1.6 배로, 맵 구조 결정의 '화면 두세 장 분량' 이다. 카메라를 붙인 뒤 실제 화면으로 걸어 확정했다.

**문은 '켜져 있으면 닫힘' 이고 메서드는 `SetDoorOpen(side, isOpen)` 이다.** 처음 이름은 `SetDoor(side, hasDoor)` 였는데
통로가 있다는 뜻의 문과 길을 막는 문짝이 한 단어에 섞여, 여는 쪽이 켜는 것인지 끄는 것인지 헷갈렸다. 부르는 쪽은 `layout.HasDoor` 의 답을 그대로 넘긴다.

**프리팹은 하나다.** GDD 의 '방 프리팹 8' 은 방 안 장애물 판단과 함께 다시 보기로 했다.

## 결과

- 방 여덟 개가 시드마다 다르게 놓이고, 이어진 방 사이 문만 열린다. U자로 붙은 두 방 사이는 닫힌다.
- 칠한 벽은 80 칸으로 계산과 정확히 같았다(프리팹 파일로 확인).
- **벽 콜라이더는 Outlines 다.** 처음 권한 Polygons 가 대각선으로 벽에 붙어 움직일 때 걸리는 버그를 냈다.
  Polygons 는 합친 벽을 볼록한 조각 여러 개로 다시 잘라, 사각형 몸의 모서리가 조각 사이 이음매에 걸린다(Box2D 의 ghost collision).
  Outlines 는 이어진 선(체인)이라 이웃 선분을 알아 걸리지 않는다. Polygons 를 고른 이유였던 '빠른 물체가 속이 빈 벽에 파고든다' 는
  플레이어가 이미 Continuous 충돌 감지라 해당하지 않았다. 마찰(재질 없음, 기본 0.4)도 후보였지만 **하나씩 바꿔 보니** Outlines 만으로 사라져 마찰은 두었다.
- Tilemap 메뉴는 우클릭한 오브젝트를 부모로 쓰지 않고 씬 루트에 `Grid` 를 만든다. 옮긴 뒤 위치를 0 으로 확인했다.

## 한계 / 남은 문제

- **`cellBounds` 는 타일을 지워도 줄지 않는다.** 칠한 적이 있는 가장 바깥을 기억해, 벽을 넓게 칠했다 지우면 방 크기가 실제보다 크게 읽히고
  방 사이 문과 문 사이에 틈이 생긴다. 벽을 다시 칠하면 `Compress Tilemap Bounds` 를 실행해야 한다. 홀수로 읽히면 `Debug.Assert` 가 알리지만
  늘어난 짝수는 잡지 못한다. 코드 주석과 이 문서로만 지킨다.
- **방 안 장애물은 넣지 않았다.** 적이 길찾기 없이 곧장 쫓아 장애물 뒤에서 멈춘다. 넣는다면 플레이어에서 시작하는 BFS 로 칸마다 거리를 구해
  적이 거리가 줄어드는 쪽으로 걷는 흐름장(flow field)까지 가야 한다. 적 AI 를 다시 여는 일이라 기능 후보 풀에 올렸고,
  4-C 에서 적이 방을 채운 뒤에도 비어 보이면 명세를 만든다. [한 줄 걷기 결정](room-layout-linear-walk.md)이 넘긴 'BFS 를 실패할 수 있는 자리로' 는 다시 미뤄졌다.
- 방이 모두 같은 모양이다. 판마다 달라지는 것은 방 순서와 이어지는 방향, 바닥 색뿐이다.
- 벽 타일 스프라이트는 2D 스프라이트 패키지의 기본 `Square` 다. 옛 벽과 같다.
