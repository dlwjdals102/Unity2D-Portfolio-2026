# 적이 장애물에 끼던 원인 다섯과, 판단을 하나로 줄여 고친 과정

## 문제

장애물을 넣자 적이 멈추거나 떨었다. **증상이 다섯 번 모양을 바꿔 가며 나왔고, 원인은 매번 달랐다.**
길찾기(격자와 BFS)는 한 번도 틀리지 않았다. 로그로 확인했다(격자가 아는 막힌 칸 수 = 거리표를 만들 때의 수, 기즈모의 빨간 테두리 = 칠한 타일).
**원인은 전부 '적이 그 길을 따라 몸을 움직이는 방식' 에 있었다.**

## 원인과 고친 것

### 1. 시야를 굵기 0 인 선으로 봤다

'플레이어가 보이면 곧장 간다' 를 `Physics2D.Linecast` 로 판정했다. 적의 몸은 1 × 1 인데 선은 점이라,
**선은 모서리를 비껴가고 몸은 걸리는** 자리가 생긴다. 그러면 직선과 우회가 프레임마다 번갈아 뽑혀 제자리에서 떤다.

굵은 원을 굴리는 `CircleCast` 로 바꿔 판정이 몸과 같은 것을 보게 했다(뒤에 시야 판정 자체를 없애며 이 코드는 사라졌다).

### 2. 마찰이 옆 방향까지 멈췄다

로그의 숫자가 답이었다.

```
길 안내 (-0.37, 0.93)    접촉 법선 (0, -1)
벽에 수직인 성분 0.93,  벽을 따라가는 성분 0.37
0.37 / 0.93 = 0.398  ≤  Unity 2D 기본 마찰 0.4
```

**이 비율이 마찰 계수보다 작으면 미끄러지지 못하고 붙는다(정지 마찰).** 방향은 멀쩡한데 속도가 정확히 0 이 되던 이유다.
마찰 0 짜리 `PhysicsMaterial2D` 를 만들어 벽과 장애물 콜라이더에 붙였다. 2D 의 마찰은 두 값의 곱의 제곱근이라 한쪽이 0 이면 0 이다.

### 3. 네모 꼭짓점을 정면으로 받았다

정확히 대각선에 있는 장애물로 직진하면 네모의 꼭짓점이 장애물 꼭짓점에 정면으로 부딪힌다.
밀려나는 방향이 진행 방향과 정확히 반대라, 마찰이 0 이어도 옆으로 흘릴 성분이 없다.
**적 콜라이더를 원으로 바꿨다.** 원은 조금만 어긋나도 미끄러진다.

### 4. 판단이 둘이라 경계에서 다퉜다

'보이면 직선, 안 보이면 우회' 는 **기둥 그늘의 경계에 선을 만든다.** 적이 그 선 위를 걸으면 매 순간 다른 답이 나온다.

```
그늘 안 → 우회(옆으로) → 그늘 밖으로 나옴 → 직선(플레이어 쪽) → 다시 그늘 안 → 반복
```

들어갈 때와 나갈 때 기준을 다르게 주는 히스테리시스(반지름 0.5 와 1.1)를 넣어 봤지만 **경계 자체는 남아** 같은 자리에서 맴돌았다.
**시야 판정을 없애고 판단을 하나로 만들었다.** 적은 거리표만 본다.

### 5. 4방향에서 좌우가 동점이었다

기둥을 사이에 두고 적과 플레이어가 일직선이면 좌우 이웃의 거리가 똑같고, 플레이어 쪽 직선과 이루는 각도까지 같아 동점을 가를 수 없다.
0.4 초마다 다시 고를 때 반대쪽이 뽑히면 되돌아가, 제자리에서 꿈틀거린다.
**이웃을 여덟로 늘려 대각선이 한 걸음 가깝게 만들어 동점을 깼다.** 근거는 [장애물과 흐름장](obstacles-and-flow-field.md)에 있다.

## 원인을 잡은 방법

추측을 여러 번 냈고 **전부 틀렸다**(폭 1 통로, 다른 방의 격자, 격자와 타일의 어긋남, 격자에 장애물이 안 들어감).
실제로 원인을 잡은 것은 셋이다.

| 도구 | 무엇을 보여 줬나 |
|---|---|
| **끼임 로그** | 상태, 위치, 넣으려는 방향, 비켜 가기, **접촉점의 법선과 파고듦**, 격자가 아는 이웃 거리 |
| **기즈모** | 격자가 막혔다고 아는 칸(빨간 테두리)과 칠한 타일이 겹치는지 |
| **파이썬 시뮬레이션** | 같은 알고리즘을 200판 돌려 폭 1 통로 수, 덩어리 사이 거리, 실패율 |

**'움직이지 않는다' 를 속도로 재면 안 된다.** 떨고 있으면 속도는 0 이 아니다. 위치가 얼마나 옮겨졌는지로 재야 로그가 걸린다.
처음에 속도로 재는 바람에 로그가 한 번도 찍히지 않았다.

## 얹었다가 전부 뺀 것들

| 넣었던 것 | 왜 뺐나 |
|---|---|
| 시야로 직선 돌진(두 번) | 판단이 둘이 되어 경계에서 다툰다 |
| 0.5 초 못 움직이면 직선을 끄는 안전망 | **버그를 가린다.** 원인이 남아 있어도 확인 단계에서 안 보인다 |
| 방향을 초당 540도씩 돌려 부드럽게 | 이웃이 여덟이 되어 꺾이는 각도가 45도로 줄자 필요가 없어졌다 |

셋 다 '판단을 하나 더 얹어 증상을 덮는' 쪽이었다. **원인을 고치자 전부 필요 없어졌다.**

## 결과

- 적은 거리표가 주는 다음 칸으로만 걷는다. 조종에 쓰이는 판단이 하나다.
- 벽과 장애물에는 마찰 0 재질이, 적에는 원형 콜라이더가 붙었다.
- 끼임 로그와 기즈모는 에디터 전용으로 남겼다. 안전망이 아니라 **감지 장치**라 성격이 다르다.

## 한계 / 남은 문제

- **적이 오래 멈추는 경우에 대한 안전망이 없다.** 지금 없어도 되는 것을 확인했지만, 한 마리가 영영 멈추면 방이 깨지지 않는다.
  Phase 6 빌드 전에 다시 본다.
- **Physics2D 의 기본 마찰(0.4)에 기대고 있다.** 프로젝트 설정을 바꾸는 대신 재질을 붙였으므로, 새 벽이나 장애물이 생기면 재질을 붙여야 한다.
- 적끼리의 밀어내기(2-C)는 그대로다. 여럿이 좁은 곳에 몰릴 때의 거동은 따로 본 적이 없다.
