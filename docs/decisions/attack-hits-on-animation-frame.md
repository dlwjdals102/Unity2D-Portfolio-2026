# 공격 판정을 버튼 프레임에서 칼이 뻗는 프레임으로 옮긴다

## 문제

근접 판정은 공격하는 순간 겹침 쿼리 한 번이었다. 입력을 받은 프레임에 `AreaHit.Box` 가 돌고
범위 표시도 같이 떴다. 그림이 도형일 때는 어긋날 것이 없었다.

**휘두르는 동작을 붙이자 아직 휘두르지 않았는데 적이 죽었다.** 동작이 시작되는 프레임에 판정이 나가고
칼은 그 뒤에 뻗는다.

프레임마다 알파 범위를 재서 칼이 언제 나가는지 확인했다.

```
char_attack_right  6프레임, 각 32x48

frame 0   폭 12   몸만 있다. idle 과 같은 폭이다
frame 1   폭 13   거의 몸만. 위로 7픽셀 올라간다 (치켜든다)
frame 2   폭 21   오른쪽으로 뻗었다        <- 여기서 칼이 나간다
frame 3   폭 21   뻗은 상태
frame 4   폭 21   뻗은 상태
frame 5   폭 12   거뒀다
```

예비 동작이 둘이라 **어긋남이 동작 길이의 3분의 1**이다. 동작 길이를 공격 간격에 맞췄으므로
활은 0.05초, 검은 0.17초다. 활은 거의 안 보이고 검은 보인다.

## 검토한 대안

### (가) 그대로 둔다

처음에 고른 쪽이다. 이유가 둘이었는데 둘 다 서지 않았다.

**'애니메이션 이벤트는 메서드 이름을 문자열로 부른다'** 고 했는데, `unity-csharp.md` 가 금지한 목록은
`SendMessage`, `Invoke("이름")`, `Animator.Play("이름")` 이고 애니메이션 이벤트는 거기 없다.
에디터에서 찍는 것이라 성격도 다르다. 규칙을 넓게 당긴 것이었다.

**'판정 시점을 옮기면 전투가 바뀐다'** 는 사실이지만, 바뀌는 쪽이 나쁘다는 근거가 없었다.
그리고 **근접 무기가 둘인 게임에서 칼이 안 나갔는데 적이 죽는 장면**이 영상에 남는다.

### (나) 예비 동작을 버리고 `frame 2` 부터 재생한다

지연도 불일치도 없앨 수 있다. 버튼을 누르면 이미 뻗은 그림이 나온다.
빈딩 오브 아이작이나 엔터 더 건전의 총처럼 반응성을 먼저 두는 방식이다.

**휘두르는 동작 자체가 사라지는 것이 문제였다.** 6프레임 중 4프레임만 쓰고, 무기를 바꾼 티가 나지 않는다.
활이 기본 무기라 반응성이 중요하다는 점은 이쪽이었지만, 검과 창이 있는 이상 휘두르는 그림이 읽혀야 한다.

### (다) 판정을 `frame 2` 로 옮긴다

고른 쪽이다. 입력에서 판정까지 **공격 간격의 3분의 1** 만큼 지연이 생기는데,
느린 무기일수록 길어지는 것이 오히려 맞는 방향이다. 묵직한 무기가 늦게 나간다.
하데스나 소울류가 공격마다 액티브 프레임을 두는 것과 같다.

## 따라온 것

### 공격 한 번에 쓸 값을 시작할 때 묶는다

판정이 밀리면 **버튼을 누른 때와 공격이 나가는 때 사이에 값이 바뀔 수 있다.**

```
무기      휘두르는 중에 숫자 키를 누르면 든 적 없는 무기로 공격이 나간다
조준 방향  마우스를 돌리면 몸이 보는 쪽과 판정이 나가는 쪽이 갈린다
```

무기와 방향과 피해량을 공격 시작에 잡아 두고 이벤트가 그것을 쓴다. 몸이 이미 그쪽으로 돌아간 상태로
휘두르므로 그림과 판정이 맞는다. 휘두르는 중에 판정 방향이 홱 바뀌면 예측할 수 없다.

**위치만 묶지 않는다.** 휘두르는 동안 걸어가면 그림도 따라가므로 판정도 지금 자리에서 나가야 한다.

**쿨다운은 버튼을 누른 시점에 시작한다.** 이벤트 시점으로 옮기면 간격이 지연만큼 늘어나
연사 스탯이 그만큼 깎인다.

### 이름이 접근 제한자에 기대고 있었다

받는 쪽 이름을 `CharacterAnimator.OnAttackFrame` 과 같게 두었다가 바꿨다.
**Unity 는 접근 제한자와 무관하게 이름을 센다.** 에디터의 Animation Event 창이 내는
`Duplicated Functions` 목록에 `private` 메서드가 올라오는 것으로 확인했다.
같은 오브젝트에 같은 이름의 메서드가 둘이면 한 번의 공격에 둘 다 불린다.

플레이어는 `FirePendingAttack`, 원거리 적은 `FireShot` 이다.
**`OnAttackFrame` 이라는 이름은 클립과 `CharacterAnimator` 두 곳에만 있다.**

### 동작이 끊기면 공격이 소실된다

이벤트가 유일한 호출 경로라 동작이 중단되면 공격이 나가지 않는다. 쿨다운은 이미 돌아간 뒤다.

코드 안전망을 넣지 않고 **Animator 전환으로 막았다.** 공격 상태에서 나가는 전환에 `Exit Time 1` 을 두어
동작이 끝까지 재생된다. 증상을 덮는 대신 원인 쪽을 막는 처리다.

## 적도 같은 구조로 갔다

원거리 적은 다르게 갈 뻔했다. 어긋남이 **10프레임 중 9번째**라 `AimTime 0.5` 기준 0.05초이고,
`TickEngaged` 가 거리 조건으로 조준을 그만둘 수 있어 **상태가 바뀐 뒤 이벤트가 도착하는 경우**를
막아야 한다고 봤다.

둘 다 서지 않았다. 0.05초는 60fps 에서 세 프레임이지만 **구조를 둘로 가를 값어치는 없고**,
상태가 바뀐 뒤 도착하는 문제는 **지금 코드도 쏘고 나서 거리를 검사하므로** 성격이 같았다.
조준이 끝나는 순간 멀어져 있어도 이미 쏘고 추적으로 간다.

그래서 `RangedEnemy` 도 `State.Aim` 에서 타이머를 보지 않고 이벤트가 발사를 결정한다.
`_stateTimeLeft` 는 `Cooldown` 에서만 쓰인다.

## 결과

- 칼이 뻗는 순간에 적이 맞고, 범위 표시도 같은 순간에 뜬다
  (`MeleeWeapon.Attack` 안에 판정과 표시가 나란히 있어 함께 옮겨졌다)
- 연사를 올려도 동작과 판정이 함께 빨라진다. 동작 길이를 `AttackSpeed` 에서 끌어오기 때문이다
- `PlayerAttack` 에 `_pending` 필드 셋이 늘었다
- 전투 로직 자체는 그대로다. `Weapon`, `AreaHit`, `Health` 가 한 줄도 바뀌지 않았다
