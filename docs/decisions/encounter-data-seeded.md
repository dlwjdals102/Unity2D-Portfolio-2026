# 웨이브는 손으로 짠 조합 에셋이고, 방마다 배치와 같은 시드로 하나 뽑는다

## 문제

방마다 무엇이 몇 마리 나올지 정해야 했다. GDD 는 '방 1개당 웨이브 2~3' 만 정해 두었다.

## 검토한 대안

| 안 | 모양 | 판단 |
|---|---|---|
| 코드에 적는다 | 방 종류별로 `switch` | 조합을 늘릴 때마다 코드를 고친다 |
| **손으로 짠 조합 에셋** | ScriptableObject 하나가 방 하나의 전투. 웨이브마다 '적 종류와 수' | 엔터 더 건전이 방마다 손으로 짠 웨이브를 쓴다. 에셋을 더하면 전투가 는다 |
| 점수 예산으로 뽑는다 | 적마다 점수를 매기고 방 예산만큼 채운다 | 하데스 방식이다. 튜닝할 값이 늘어 6번 난이도 튜닝과 겹친다. 지금 정하면 두 번 정하는 셈이다 |

CLAUDE.md 3번의 포트폴리오 예외(데이터 주도)를 적용했다. 적이 네 종류뿐이어도 조합은 데이터로 뺀다.

**Unity 직렬화는 배열의 배열을 저장하지 못한다.** `WaveEntry[][]` 는 인스펙터에 아무것도 나오지 않는다. 배열을 가진 구조체(`Wave`)의 배열로 한 겹 감쌌다.

### 어떻게 고르나

| 안 | 판단 |
|---|---|
| 방을 놓을 때 방마다 정해 `Room` 에 넣어 둔다 | 방이 전투 데이터를 들게 된다. `Room` 은 문, 색, 카메라, 상태만 안다 |
| **`RoomCombat` 이 시드 난수를 하나 들고 전투가 시작될 때마다 뽑는다** | 방은 그대로다. [한 줄 걷기](room-layout-linear-walk.md) 덕에 방문 순서가 하나뿐이라 뽑는 순서도 하나뿐이다 |

## 선택과 이유

**조합 에셋 다섯(전투 방용 넷, 보스 방용 하나)을 두고, `RoomCombat` 이 `System.Random(이번 판 시드)` 에서 전투 방마다 하나를 뽑는다.**

- **같은 시드면 방마다 같은 조합이 나온다.** 방을 도는 순서가 0번부터 한 줄로 고정이라 뽑는 순서가 흔들리지 않는다.
- **보스 방은 뽑지 않고 전용 조합을 쓴다.** 보스 방이 늘 마지막이라 앞쪽 뽑기 순서에 영향이 없다.
- **`UnityEngine.Random` 이 아니라 `System.Random` 이다.** 앞의 것은 판 전체가 공유해 다른 코드가 뽑으면 값이 밀린다.
  4-A 의 배치 생성이 같은 이유로 `System.Random(seed)` 를 쓴다. 한 파일에서 둘을 함께 쓰면 이름이 모호해져(CS0104) 어느 쪽인지 끝까지 적는다.
- **방을 깼다는 것은 `RoomCombat.OnRoomCleared(Room)` 로 알린다.** 클리어 화면이 듣고 보스 방이면 판을 끝낸다.
  '보스를 잡았다' 가 아니라 '방을 깼다' 인 이유는 **4-D 의 보상이 같은 신호를 쓰기** 때문이다.
  4-B 의 임시 클리어('보스 방에 들어가면')와, 적이 모두 죽을 때마다 뜨던 연결을 지웠다. 뒤엣것은 웨이브가 들어오자마자 첫 웨이브에서 클리어를 띄웠다.

조합의 값은 '무엇이 몇 마리' 까지만 정했다. 체력과 공격력은 6번 난이도 튜닝의 몫이다.

| 에셋 | 웨이브 |
|---|---|
| Basic | 근접 3 / 근접 2 + 분열 1 + 원거리 1 |
| Melee | 근접 3 / 근접 4 |
| Dash | 돌진 2 + 근접 1 / 돌진 3 |
| Ranged | 원거리 2 / 원거리 2 + 근접 2 |
| Boss | 근접 4 / 돌진 2 + 원거리 2 / 분열 2 + 원거리 2 |

## 결과

- 다음 웨이브로 넘기는 신호는 기존 `EnemyCounter` 의 '모두 죽음' 을 그대로 쓴다. 한 번에 한 방만 싸워 전역 개수가 곧 지금 웨이브의 개수다.
  **분열 적이 갈라지는 경우도 그대로 맞았다.** 2-C 에서 0 판정을 `LateUpdate` 로 미뤄 둔 덕에, 작은 적이 태어나는 프레임에는 알림이 가지 않는다.
- 적을 만드는 일이 `EnemyCounter` 의 `LateUpdate` 안에서 벌어지지만, 알리기 직전에 '볼 것 있음' 표시를 내려 두어 같은 프레임에 두 번 알리지 않는다.
- 조합 에셋은 `ScriptableObjects/Encounters/` 에 둔다. 에셋보다 폴더 이름을 먼저 정했고 기존 폴더와 같은 복수형이다.

## 한계 / 남은 문제

- **전투 방 여섯에 조합 넷이라 한 판에 두세 개가 겹친다.** 같은 조합이 연달아 나오는 판도 생긴다. 조합을 늘리는 것은 난이도 곡선과 함께 본다.
- **조합 뽑기 난수와 배치 난수가 같은 시드에서 출발한다.** 뽑는 대상이 달라 결과가 닮아 보이지는 않지만 두 난수열의 출발점은 같다.
- **적이 서는 자리는 시드를 따르지 않는다.** 출현 지점 고르기는 `UnityEngine.Random` 이다. 자리까지 재현하려면 방마다 난수를 따로 들어야 한다.
- 조합 배열을 비워 두면 배열 밖 접근으로 터진다. 인스펙터 실수라 터지는 쪽으로 두었다. 에셋 안쪽(빈 웨이브, 빈 프리팹 칸)은 `OnValidate` 가 경고한다.
