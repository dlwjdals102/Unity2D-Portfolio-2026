# 인접 하나로는 배치를 고민하게 만들지 못한다

## 문제

GDD 가 시너지 4종(인접·같은 행·같은 열·모서리)을 요구했다.
넷을 한꺼번에 만들지 않고 **인접 하나만 먼저 만들어 재미가 나오는지 보기로** 했다.

명세의 완료 조건에 이렇게 적었다.

> 인접 시너지 하나로 배치를 고민하게 되는지 판단한다.

## 판단 결과: 부족하다

**뭉치면 무조건 이득이라 최적해가 자명하다.**

인접 시너지는 한 방향으로만 작동한다. 이웃이 많을수록 좋고 떨어뜨릴 이유가 없다.
5×5 가방에 아이템 넷이 9칸을 쓰므로 공간 제약도 없다.
**최적 배치가 바로 보이면 그것은 퍼즐이 아니라 절차다.**

## 이것이 왜 문제인가

재미가 없다는 것보다 **문서와 게임이 어긋난다**는 쪽이 무겁다.

GDD 첫 줄이 이렇다.

> 아이템을 **어디에 놓느냐로 빌드가 갈리는** 2D 탑다운 액션 로그라이트

**면접관이 플레이해서 '다 붙이면 되네' 를 알아채면 이 주장이 거짓이 된다.**
정체성이라고 적어둔 것이 실제로는 없는 셈이다.

신입 포트폴리오에서 게임의 재미 자체는 평가 항목이 아니다.
**그러나 문서가 주장하는 것이 게임에 없으면 그것은 다른 문제다.**

## 검토한 대안

**안 A: 새로운 조건을 발명한다 (예: 고립하면 +50%)**
- 장점: 뭉치는 것과 정면으로 충돌해 선택이 생긴다.
- 단점: **GDD 의 4종에 없는 개념이다.** 문서와 또 어긋난다.

**안 B: 나머지 3종을 만든다**
- 장점: **넷이 이미 서로 충돌한다.** 발명할 것이 없다.
- 장점: 각 조건의 탐색이 EditMode 테스트 대상이라 테스트가 셋 더 붙는다.
- 단점: 계단이 늘어난다.

**안 C: 인접 하나로 두고 밸런스로 해결한다**
- 단점: 방향이 하나뿐이라 값을 어떻게 바꿔도 최적해가 자명하다.

### 넷이 어떻게 충돌하는가

| 시너지 | 유리한 배치 |
|---|---|
| 인접 | 뭉친다 |
| 같은 행 | 가로로 늘어놓는다 |
| 같은 열 | 세로로 늘어놓는다 |
| **모서리** | **네 귀퉁이로 흩는다** |

**모서리가 인접과 정면으로 부딪힌다.** 귀퉁이는 이웃이 적은 자리이기 때문이다.
같은 행과 같은 열도 서로 배타적이다.

## 선택과 이유

**B를 골랐다.** GDD 가 요구한 넷을 그대로 만들면 선택이 저절로 생긴다.

**어디까지 할지는 선을 그었다.**

| | 하는가 |
|---|---|
| 4종을 만들어 **선택이 존재하게** 한다 | **한다** |
| 밸런싱을 정교하게 다듬는다 | 하지 않는다 |
| 최적 배치를 찾기 어렵게 만든다 | 하지 않는다 |

**'선택이 있다' 까지만 보이면 된다.** 어느 배치가 최적인지 계산해야 알 정도로
만들 이유가 없다. Phase 4 에 남은 것이 아직 많고, 재미의 깊이는
신입 포트폴리오의 평가 항목이 아니다.

## 결과

- 인접 시너지가 동작한다. 검 옆에 아이템을 놓으면 검의 공격력이 오르고,
  빼면 돌아온다. **아이템 하나를 놓으면 주변 것들의 시너지도 함께 바뀐다.**
- `BagGrid` 가 인접을 세고 테스트 여덟 개가 그 규칙을 지킨다.
  대각선을 세지 않는 것, 두 칸에서 맞닿아도 하나로 세는 것,
  자기 자신을 세지 않는 것이다.
- 시너지 모디파이어는 전용 출처를 쓴다. 배치가 바뀌면 그것만 전부 지우고
  다시 계산하므로 **아이템 효과와 섞이지 않는다.**
- 가방에 스탯 표시를 붙였다. 배치를 바꿀 때마다 값이 바뀌는 것이 보인다.

## 한계 / 남은 문제

- **나머지 3종이 없어 선택이 없다.** 다음 명세에서 만든다.
- **공간이 넉넉하다.** 25칸에 아이템 넷이 9칸을 쓴다. 15종을 채우면
  달라지겠지만, 그때도 넉넉하면 가방을 줄이거나 아이템을 키워야 한다.
- **매번 전부 다시 계산한다.** 아이템 하나를 놓으면 주변 시너지가 연쇄로
  바뀌므로 증분 갱신을 하려면 연쇄를 추적해야 한다. 25칸 규모에서는
  전부 다시 세는 쪽이 단순하다.
- **스탯 표시는 디버그용이다.** Phase 5 에서 정리하거나 제대로 만든다.
