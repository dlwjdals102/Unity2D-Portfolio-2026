# 판 도중에 태어나는 적은 만든 쪽이 대상을 넣고, 스스로 태어났다고 알린다

## 문제

분열 적이 오기 전까지 적은 전부 씬에 놓여 시작했고, 그 가정이 코드 두 곳에 있었다.

| 가정 | 어디에 | 깨지면 |
|---|---|---|
| 추적 대상은 씬에서 끌어다 놓는다 | `EnemyBase._target` | 프리팹에서 태어난 적은 대상이 비어 터진다 |
| 적 수는 시작할 때 한 번 센다 | `EnemyCounter.Start` | 나중에 태어난 적을 세지 않아 클리어가 일찍 뜬다 |

두 가지 모두 **호출 순서**에 함정이 있었다.

- **`Instantiate` 는 돌려주기 전에 `Awake` 를 부른다.** 만든 뒤 대상을 넣어도 `EnemyBase.Awake` 의
  `_target.GetComponent<IDamageable>()` 가 그보다 먼저 돈다.
- **큰 적의 `Health.OnDied` 에는 세 곳이 구독한다.** 카운터(빼기), `EnemyBase`(파괴), `SplitOnDeath`(작은 적 만들기).
  카운터가 먼저 불리면 0 을 세고 클리어를 띄운 뒤에 작은 적이 태어난다.

## 1. 태어난 적이 대상을 받는 길

### 안 가: 만드는 쪽이 넣어 준다
- 장점: 씬에 놓인 적과 태어난 적이 같은 길(`Awake` → 대상 받기 → `Start`)을 지난다.
- 장점: 웨이브를 만드는 쪽도 씬 오브젝트라 같은 방식으로 넣을 수 있다.
- 단점: `Awake` 에서 대상을 쓰던 줄을 `Start` 로 옮겨야 한다. `SetTarget` 은 `Start` 전에 불러야 한다.

### 안 나: 씬에 놓인 적을 복제한다
- 장점: 씬 오브젝트를 `Instantiate` 하면 씬 참조도 복제되어 코드가 가장 적다.
- 단점: 작은 적은 큰 적과 다른 프리팹이라 쓸 수 없다. 복제할 작은 적을 씬에 숨겨 두면 보이지 않는 오브젝트에 기댄다.

### 안 다: 적이 스스로 찾는다 (`FindFirstObjectByType`)
- 장점: 넘겨줄 것이 없다. 규칙이 초기화 1회로 허용한다.
- 단점: 씬에 놓인 적은 인스펙터 값이 있어 '비었으면 찾는다' 는 두 갈래가 생긴다. 의존이 인스펙터에서 보이지 않는다.

### 안 라: 비활성 부모 밑에 만들어 `Awake` 를 미룬다
- 장점: `EnemyBase` 를 고치지 않는다.
- 단점: 순서 문제를 풀지 않고 숨긴다. 왜 부모를 끄는지가 코드에 드러나지 않는다.

### 선택

**가.** 두 갈래 없이 한 길로 지나가는 것이 결정적이었다. `EnemyBase` 에 `Target`(읽기 전용)과 `SetTarget` 을 열고,
`_targetDamageable` 을 찾는 줄을 `Start` 로 옮겼다. 그 줄 위에 옮긴 이유를 주석으로 남겼다.
코드만 보면 `Awake` 의 캐싱 줄들과 한자리에 있어야 할 것처럼 보여, 되돌리면 씬에 놓인 적은 멀쩡하고 갈라질 때만 터진다.

## 2. 적 수 세기

### 태어남을 누가 알리나

| 안 | 판단 |
|---|---|
| 태어난 적에게 카운터 참조를 넣어 준다 | `SetTarget` 옆에 넣을 것이 계속 는다. 웨이브에서는 투사체 풀까지 붙는다 |
| 갈라지는 부품이 카운터에 알린다 | 적을 만드는 곳마다 알리는 줄이 는다. 잊으면 조용히 틀린다 |
| **`EnemyBase` 의 `static` 이벤트** | 참조를 넘기지 않는다. 적은 태어났다고만 말하고 누가 듣는지 모른다 |

### 0 을 언제 판정하나

**죽는 순간 판정하면 반드시 틀린다.** 카운터는 적의 `Awake` 에서 `Spawned` 를 받아 `OnDied` 를 구독하므로,
`OnEnable` 에서 구독하는 `EnemyBase` 와 `SplitOnDeath` 보다 늘 먼저 불린다. 큰 적이 마지막으로 죽으면 카운터가 0 을 세고 난 뒤에야 작은 적이 태어난다.
설계할 때는 '구독 순서에 따라 틀릴 수 있다' 로 봤는데, 따라가 보니 틀리는 쪽으로 순서가 고정되어 있었다.

### 선택

- **적이 `Awake` 끝에서 `EnemyBase.Spawned` 로 알리고, 카운터가 받은 `Health` 의 `OnDied` 를 구독한다.**
  씬에 놓인 적과 갈라져 나온 적이 같은 길로 세어져 `Start` 의 `FindObjectsByType` 를 지웠다.
- **죽을 때는 수를 빼고 표시만 남기고, `LateUpdate` 에서 0 인지 본다.** 같은 프레임의 `OnDied` 가 모두 끝나고 작은 적이 세어진 뒤다.
- **조건은 `== 0` 이다.** 한 적을 두 번 빼는 버그가 생기면 `<= 0` 은 클리어를 일찍 띄워 원인을 가리고, `== 0` 은 클리어가 안 떠 바로 드러난다.
- **카운터에 `[DefaultExecutionOrder(-100)]` 을 붙였다.** 씬이 열릴 때 적의 `Awake` 가 카운터의 구독보다 먼저 돌면 그 적을 세지 못한다.
  에디터에서는 맞다가 빌드에서 틀릴 수 있는 종류라 순서를 속성으로 못박았다.

## 결과

- **`MeleeEnemy` 는 한 줄도 바뀌지 않았다.** 분열 적은 `MeleeEnemy` 에 `SplitOnDeath` 부품 하나를 붙인 프리팹이다.
  [FSM 구조 결정](enemy-fsm-structure.md)이 '분열은 근접 적에 죽으면 쪼개지는 부품을 붙이는 쪽이 자연스럽다' 고 본 것이 맞았다.
  갈라지는 일은 살아 있는 동안의 행동이 아니라 죽는 순간 한 번 일어나는 일이라 상태 머신 밖에 있다.
- `SplitOnDeath` 는 `OnDestroy` 가 아니라 `Health.OnDied` 에서 갈라진다. `OnDestroy` 는 씬을 떠날 때와 플레이를 멈출 때도 불려,
  그때 적을 만들면 정리되지 않은 오브젝트가 남는다.
- 큰 분열 적을 마지막에 죽여도 클리어가 뜨지 않고, 작은 적까지 모두 죽이면 한 번 뜬다. 다시 시작해도 같다.
- 바뀐 곳은 `EnemyBase` 에 이벤트 선언과 호출 한 줄씩, `Start` 로 옮긴 한 줄, `Target` 과 `SetTarget` 이고,
  `EnemyCounter` 는 `Start` 가 없어지고 `OnEnable`, `LateUpdate`, `OnDisable` 로 바뀌었다.
- **EditMode 테스트는 붙이지 않았다.** 적 수 세기를 떼어 내면 정수 하나와 표시 하나라 더하고 빼기를 시험하게 된다.
  진짜 버그는 한 프레임 안의 호출 순서라 Unity 가 도는 중에만 드러난다.

## 한계 / 남은 문제

- **`SetTarget` 은 `Start` 전에 불러야 한다.** 그 뒤에 대상을 바꾸면 피해 받을 곳이 옛 대상에 남는다. 대상을 바꾸는 기능이 없어 주석으로만 지킨다.
- **원거리 적의 투사체 풀은 아직 넣어 주는 길이 없다.** 갈라져 나오는 것이 근접 적뿐이라서다. 원거리 적을 런타임에 만드는 웨이브에서 같은 방식으로 연다.
- **`health.OnDied` 는 해제하지 않는다.** 구독 목록은 `Health` 가 들고 있어 적이 파괴되면 목록째 치워진다.
  해제하지 않아 쌓이는 것은 이벤트를 가진 쪽이 오래 살 때이고, 그래서 `static` 인 `Spawned` 는 `OnDisable` 에서 해제한다.
  규칙('구독은 해제와 짝')에서 벗어난 자리라 주석을 달았다. **적을 풀링하면 `Health` 가 살아남아 두 번 구독되고 한 적이 두 번 빠진다.**
- **`static` 이벤트는 해제를 잊어도 화면에 증상이 없다.** 다시 시작할 때마다 파괴된 카운터가 구독 목록에 쌓이지만 새 카운터의 수는 맞다.
  테스트로 못 잡고 규칙으로만 지킨다.
- **실행 순서 속성은 코드 밖의 약속이다.** 카운터보다 먼저 돌아야 하는 스크립트가 생기면 순서를 다시 본다.
