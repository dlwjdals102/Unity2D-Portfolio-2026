# 14주 로드맵

원칙 세 가지.

1. **넓히기 전에 뚫는다.** 재미없어도 좋으니 "시작→플레이→죽음→재시작"이 도는 상태를 4주 안에 만든다.
2. **매주 커밋한다.** 커밋 히스토리 자체가 포트폴리오다. 한 번에 몰아 올린 저장소는 의심받는다.
3. **게임에 100%를 쓰지 않는다.** 국내 공채는 CS·알고리즘 필기를 본다. 게임 70% / CS·알고리즘 20% / 문서·이력서 10%.

## Phase 5 — 폴리싱 (11~12주차)
"완성도 있어 보이게" 만드는 구간. 투자 대비 인상 개선이 가장 큰 구간이다.
- [x] 히트스톱 / 카메라 셰이크 / 피격 플래시
- [x] 보스 등장 연출 (스케일로 커지며 나타나고, 그동안 시야가 방 전체로 넓어진다)
      **한 번 뺐다가 되돌렸다.** 기술적으로 남는 것이 없다고 보고 뺐는데, 보스 방만 시야를
      넓히면서 전환이 툭 튀어 다시 필요해졌다. 비용은 컴포넌트 하나와 코루틴 하나였다
- [x] 사운드 (클립 셋. 타격음, 휘두르는 소리, BGM. 믹서·풀링·거리 감쇠는 하지 않았다)
      **휘두르는 소리는 이 범위를 한 번 넘은 것이고 이유를 명세에 적었다.** 빗나간 공격에 아무 반응이 없었다.
- [x] 메타 진행 저장 / 로드 (런 중간 저장은 만들지 않는다. GDD 5번)
      **마을 씬이 함께 들어갔다.** 범위를 넘은 것이고, 돌아오는 시점이 판이 끝난 뒤라
      씬을 넘는 것이 값 넷뿐이어서 가능했다. 이유는 명세에 적었다.
- [ ] CC0 에셋 도입 + 출처 기록 (실패해도 제출 가능한 상태 유지)
- [x] 이동 애니메이션과 무기 휘두르기 (Animator 로 엮었고 공격 판정을 애니메이션 이벤트로 옮겼다)
- [x] UI 정리 (디버그 표시를 치우고 체력 바 둘의 방식을 맞추는 데까지. 새 레이아웃은 만들지 않는다)
      **창이 열린 동안 공격 입력을 막는 것과 보상 넘어가기가 함께 들어갔다.** 둘 다 범위를 넘은 것이고 이유를 명세에 적었다.
- [x] 카메라 크기 (방을 20x12 로 줄였고, 보스 방은 전투가 시작될 때 방 전체로 넓어진다)
- [~] 프로파일러로 GC Alloc·드로우콜 점검 **(Phase 6 의 실행 빌드로 옮겼다)**
      에디터에서 재면 `EditorLoop` 이 85%를 차지해 숫자가 쓸모없다. 한 번 겪었다.
      측정할 것 셋(총알 풀의 부모 유무, 적 분리의 물리 스텝 비용, GC Alloc)도
      전부 '개발 빌드에서 다시 잰다' 로 적혀 있어 빌드 항목과 묶는 편이 낫다.

## Phase 6 — 포장 (13~14주차)
실제 서류 통과를 결정하는 구간. 절대 생략하지 말 것.
- [~] 플레이 영상 1분 27초. **녹화는 끝났고 편집이 남았다**
      처음 2~3분으로 잡고 '앞 15초에 가장 화려한 장면' 을 두려 했는데 둘 다 바꿨다.
      보여줄 그림이 약해서 길어지면 **같은 방에서 같은 적을 더 오래 때리는 화면**이 늘고,
      여는 하이라이트는 찍어 놓고 보니 보스 구간과 같은 화면이었다.
      **짧은 영상에는 예고편이 들어갈 자리가 없다.** 그 역할은 README 의 GIF 가 대신한다
- [x] 실행 빌드 (Windows). 다운로드 링크는 README 정비에서 붙인다
      창 모드 1600 x 900 으로 비율을 고정해 **해상도와 울트라와이드 문제를 일어나지 않게 했다.**
      빌드 전에 확인할 것 일곱을 적어 두고 전부 지났으며, 그중 둘(마을에서 무기를 들지 않는 것,
      방 개수가 3 으로 박힌 것)은 실제로 빌드에서만 드러난 문제였다
- [~] README 정비. 짧게 둔다. 명세는 `specs/portfolio-pages.md`
- [ ] **노션 포트폴리오 페이지**: 구조 다이어그램 + 핵심 설계 3가지 상세 설명
      처음에는 저장소 안의 기술 문서로 적어 두었는데 노션으로 바꿨다.
      **이력서에 넣는 링크로 노션이 사실상 표준이고, 면접관 상당수가 GitHub 를 열지 않는다.**
      입구를 셋으로 가른다. 노션이 읽히는 곳, README 가 30초 판단, `docs/` 가 근거다.
      **`docs/` 를 노션에 복사하지 않는다.** 두 벌이 되면 한쪽만 고치는 날이 온다
- [ ] **WebGL 빌드 + GitHub Pages.** 노션 다음이다
      **출처 셋이 공통으로 '실행 가능한 빌드' 를 말했다**(영어권 가이드의 itch.io WebGL,
      GitHub Pages 로 띄운 사례, apk 링크를 단 사례). 지금은 Windows exe 뿐이라
      받아서 압축을 풀어야 하고, 브라우저에서 바로 돌면 그 장벽이 사라진다.
      **비용을 모르는 항목이다.** 세이브가 `Application.persistentDataPath` 에
      `File.WriteAllText` 라 WebGL 에서 어떻게 도는지 확인하지 않았다.
      다만 저장 실패가 이미 try/catch 로 막혀 있어 **최악이 '해금이 남지 않는 데모'** 이고
      한 판을 보여주는 목적에는 그래도 쓸 만하다.
      **확인 순서:** 빌드를 내보내고 브라우저에서 (가) 소리가 나는지
      (나) 한 판이 끝나는지 (다) 새로 고침 뒤 해금이 남는지
- [ ] 이력서 / 자기소개서. **주 링크가 노션이라 노션이 먼저 끝나야 한다**
      노션을 PDF 로도 내보낸다. 첨부파일을 요구하는 지원 양식에 쓴다
- [ ] **개발 빌드로 프로파일링** (맨 뒤로 옮기고 범위를 줄였다)
      **서류를 통과시키는 것은 영상과 README 와 이력서이고, 프로파일링은 면접에 가서 쓰는 재료다.**
      적 생성 비용 측정은 뺐다. 한 웨이브가 최대 4마리라 예상이 틀릴 여지가 작고,
      '4마리라 문제가 되는 규모가 아니었다' 로 설명이 된다. 적 풀링도 넣지 않는다.
      남긴 것은 **PerfTest_Projectiles 씬에서 투사체 풀링 전후 캡처 둘과 일반 플레이 한 판 캡처 하나**다.
      이미 만든 풀링의 효과를 뒷받침할 수치가 Phase 3 에서 에디터로 재어 오염돼 있다
