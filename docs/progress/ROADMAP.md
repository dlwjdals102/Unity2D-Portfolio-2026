# 14주 로드맵

원칙 세 가지.

1. **넓히기 전에 뚫는다.** 재미없어도 좋으니 "시작→플레이→죽음→재시작"이 도는 상태를 4주 안에 만든다.
2. **매주 커밋한다.** 커밋 히스토리 자체가 포트폴리오다. 한 번에 몰아 올린 저장소는 의심받는다.
3. **게임에 100%를 쓰지 않는다.** 국내 공채는 CS·알고리즘 필기를 본다. 게임 70% / CS·알고리즘 20% / 문서·이력서 10%.

---

## Phase 1 — 세팅 (1주차)
- [x] Git 저장소 + Git LFS + .gitattributes
- [x] Unity 버전 고정 (Unity 6.3 LTS / 6000.3.9f1)
- [x] 폴더 구조 확정
- [x] GDD 1장 작성 (`docs/design/GDD.md`)
- [x] 문서 체계 구축 (`docs/README.md`)
- [x] 아트 방침 확정 (도형 프로토타입 우선, 에셋 도입은 Phase 5)

## Phase 2 — 수직 슬라이스 (2~4주차)
목표: **못생겼지만 끝까지 도는 게임 하나.**
- [ ] 플레이어 이동 / 공격 / 피격 / 사망
- [ ] 적 1종 (추적 + 공격)
- [ ] 방 1개, 적 전멸 시 클리어
- [ ] 타이틀 → 인게임 → 게임오버 → 재시작 씬 흐름
- [ ] HP UI

> 이 단계가 끝나야 "게임을 만들어 본 사람"이다. 여기서 막히면 스코프를 더 줄인다.

## Phase 3 — 시스템화 (5~7주차)
목표: **콘텐츠를 코드 수정 없이 추가할 수 있는 구조로 리팩터링.**
- [ ] 적 AI를 상태 머신(FSM)으로 정리
- [ ] 투사체·이펙트 오브젝트 풀링
- [ ] 적/아이템/무기 데이터를 ScriptableObject로 분리
- [ ] 스탯 + 모디파이어(버프/디버프 중첩) 시스템
- [ ] 이벤트 기반 UI 갱신 (Update 폴링 제거)

> **면접 질문의 90%가 이 구간에서 나온다.** 각 선택마다
> "왜 이 구조를 골랐고, 대안은 무엇이었는가"를 메모로 남길 것.

## Phase 4 — 콘텐츠 확장 (8~10주차)
- [ ] 무기 3종 (근접 / 원거리 / 광역). GDD 스코프 표 기준
- [ ] 적 4종 + 보스 1기
- [ ] 아이템 20종 + 시너지 규칙 4종
- [ ] 절차적 방 배치
- [ ] 난이도 곡선 튜닝

## Phase 5 — 폴리싱 (11~12주차)
"완성도 있어 보이게" 만드는 구간. 투자 대비 인상 개선이 가장 큰 구간이다.
- [ ] 히트스톱 / 카메라 셰이크 / 피격 플래시
- [ ] 사운드 (타격음, BGM)
- [ ] 메타 진행 저장 / 로드 (런 중간 저장은 만들지 않는다. GDD 5번)
- [ ] CC0 에셋 도입 + 출처 기록 (실패해도 제출 가능한 상태 유지)
- [ ] 프로파일러로 GC Alloc·드로우콜 점검 **(전후 수치를 캡처해 둘 것)**

## Phase 6 — 포장 (13~14주차)

- [ ] 플레이 영상 2~3분 (앞 15초에 가장 화려한 장면)
- [ ] 실행 빌드 (Windows) + 다운로드 링크
- [ ] 기술 문서: 구조 다이어그램 + 핵심 설계 3가지 상세 설명
- [ ] README 정비
- [ ] 이력서 / 자기소개서
