## Q2. 왜 속도는 `Awake` 에서 정하고 피해량은 `Launch` 에서 정했나요?

> **셋 중 가장 좋은 질문이다.** 풀링과 데이터 분리가 만나는 지점이라,
> 두 시스템을 다 이해했다는 것이 한 답변에 드러난다.
>
> 꼬리질문 후보: "그럼 속도에 버프가 붙으면 어떻게 하실 건가요?"

**내 답변**

투사체는 풀에서 재사용됩니다. 한 번 만들어지면 Awake 가 다시 돌지 않습니다.
그래서 발사할 때마다 달라져야 하는 값을 Awake 에 두면 안 됩니다.

속도와 수명은 투사체 종류의 성질이라 안 바뀝니다. Awake 에서 데이터를 읽습니다.
피해량은 발사하는 쪽이 정하고 매번 달라질 수 있어서 Launch 로 받습니다.

피해량을 Awake 에 뒀다면, 공격력이 1 에서 3 으로 올라도
이미 풀에 들어가 있던 투사체는 계속 1 로 나갑니다.
새로 만들어지는 것만 3 이라 같은 무기인데 투사체마다 데미지가 달라집니다.
오류가 안 나고 값만 이상해서 찾기 어렵습니다.

기준은 하나입니다. 발사할 때마다 새로 정해져야 하는 값인가.
그렇다면 Launch, 아니면 Awake 입니다.

풀링을 먼저 만든 덕에 이 구분이 생겼습니다.
순서가 반대였으면 데이터를 옮긴 뒤에 다시 손댔을 겁니다.

**보완**

**[3] 기준(런타임에 바뀌면 Launch, 아니면 Awake)은 직접 찾은 것이다.**
이 문항의 핵심이고, 한 줄로 말할 수 있으면 새 값을 만나도 판단할 수 있다.

Claude 가 보탠 것은 둘이다. 왜 그 기준이 나오는지(풀 재사용으로 Awake 가
다시 안 돈다), 그리고 잘못 뒀을 때의 실패 장면.

**외우지 않는다.** 읽고 덮은 뒤 말해 본다.
첫 문단만 기억하면 나머지는 따라 나온다.

꼬리질문 대비:
- "속도에 버프가 붙으면요" → Launch 로 옮긴다. **발사 시점의 스탯을 받아야
  하므로 지금 피해량과 같은 처지가 된다.** 근거를 붙여 확신 있게 말한다
- "적도 풀링하면요" → 같은 문제가 생긴다. 지금 EnemyController 가 Awake 에서
  최대 체력을 넣는데, 재사용하면 체력 0 으로 되살아난다.
  **아직 안 고쳤고 STATUS 정리 목록에 있다**
- "왜 Launch 가 인자를 받게 했나요" → 투사체가 자기 피해량을 모르게 하려고.
  같은 투사체를 적이 쏘거나 무기 여러 종이 공유해도 각자 공격력이 실린다

## Q3. 데이터 클래스를 `get` 만 있는 프로퍼티로 노출한 이유가 있나요?
