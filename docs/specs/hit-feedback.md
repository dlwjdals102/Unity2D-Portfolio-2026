# 타격 피드백

## 왜 필요한가

**포트폴리오에 필요해서다.** Phase 6 에서 플레이 영상을 찍는데 지금은 맞아도 화면에 아무 일이 없다.
적은 소리 없이 체력만 줄고, 플레이어는 무적 깜빡임뿐이다.

게임에도 필요하다. **적이 맞았는지 안 맞았는지 지금은 구분이 안 된다.**
적의 무적 시간이 0 이라 `Health` 의 깜빡임이 돌지 않는다.

가져갈 것은 구조뿐이다. 수치와 에셋은 밖으로 뺀다
([폴리싱에서 프로그래머가 가져갈 것만 가져간다](../decisions/polish-scope.md)).

## 동작 정의

- 적이 맞으면 **그 적만** 한 번 밝게 번쩍이고 곧 제 색으로 돌아온다.
- 번쩍임이 끝난 적의 색은 **그때의 상태 색**이다. 쫓는 중이면 파랑, 대기면 빨강이다.
- 번쩍이는 동안 상태가 바뀌면 **바뀐 상태의 색**으로 돌아온다. 옛 색이 남지 않는다.
- 플레이어가 맞으면 **시간이 짧게 멈추고 화면이 흔들린다.** 지금의 무적 깜빡임은 그대로다.
- 적이 맞아도 시간이 멈추고 화면이 흔들린다. **플레이어가 맞을 때보다 약하다.**
- **시간이 멈춘 동안에도 화면 흔들림은 움직인다.**
- 여럿이 한꺼번에 맞아도 **멈추는 시간이 겹쳐 길어지지 않는다.** 긴 쪽 하나만 적용된다.
- **흔들림도 겹쳐 세지지 않는다.** 가장 센 것 하나만 적용된다.
  연사를 올리는 아이템을 집어도 화면이 더 흔들리지 않는다.
- **아이템을 집어 최대 체력이 늘 때는 아무 일도 일어나지 않는다.**
- 무적인 대상을 때리면 아무 일도 일어나지 않는다. 보스의 페이즈 전환 중이 그렇다.

## 경계 — 이 기능이 하지 않는 것

- **넉백.** 매 물리 스텝 속도를 덮어써서 다음 스텝에 사라진다
  ([movement-no-inertia.md](../decisions/movement-no-inertia.md)). 넣으려면 '덮어쓰지 않는 구간' 을 만들어야 한다.
- **사운드.** 폴리싱의 다음 항목이다. 타격 지점은 이 기능이 만들어 두므로 거기에 붙인다.
- **파티클, 이펙트 오브젝트.** 색 교체로 끝낸다.
- **셰이더나 머티리얼 작업.**
- **셰이크를 직접 만드는 것.** Cinemachine Impulse 를 쓴다.
- **일시정지 기능.** `timeScale` 을 쓰는 두 번째 기능이 생길 때 다시 본다.
- **수치 맞추기.** 데이터로 빼고 한 번 정한다. 측정도 비교도 하지 않는다.
- **피해량에 따라 세기를 달리하기.** 이벤트에 피해량을 싣지 않는다. 필요해지면 그때 늘린다.

## 설계

### 맞은 쪽이 알린다

적이 맞았다는 것은 **플레이어가 때렸다는 것과 같다.** 적은 서로를 때리지 않는다
([EnemyBase.cs:228](../../Assets/_Project/Scripts/Enemy/EnemyBase.cs:228)).
그래서 근접과 투사체를 구분할 필요가 없고 경로가 하나다.

버린 안은 **때린 쪽이 알리는 것**이다. `Projectile` 이 누가 쐈는지 모르고
([Projectile.cs:33](../../Assets/_Project/Scripts/Combat/Projectile.cs:33)),
레이어를 보게 하거나 풀마다 켜고 끄게 하면 **인스펙터 설정에 동작이 걸린다.**
static 싱글턴도 버렸다.

### 주입이 필요한 것은 히트스톱 하나뿐이다

처음에는 '대상별 반응' 과 '전역 반응' 두 층으로 갈라 적었다. 셰이크를 전역으로 봤는데
**계단 3에서 그것이 틀린 것을 알았다.** `CinemachineImpulseSource` 는 위치를 갖는 컴포넌트라
맞은 대상에 붙고, 전역으로 중계하는 일은 패키지의 매니저가 한다.

```
히트스톱   씬에 하나. Time.timeScale 은 하나뿐이다.          적에게는 생성할 때 주입한다
셰이크     대상마다 ImpulseSource. 패키지 매니저가 중계한다.  주입이 없다
플래시     대상마다. 자기 SpriteRenderer 를 칠한다.          주입이 없다
```

**셋 중 둘이 주입을 필요로 하지 않는다.** 전역으로 보이는 반응이라도 '어디서 일어났는가' 를
값으로 들고 있으면 대상에 붙을 수 있다. 시간만은 그럴 수 없다.

**주입할 곳은 셋이다.** `RoomCombat` 의 적 생성, `Boss` 의 소환, `SplitOnDeath` 의 갈라지기다.
처음에 둘로 세었다가 계단 2에서 셋인 것을 알았다.

`EnemyBase` 가 받아 보관하고 자기 `HitReaction` 에 넘긴다. `SetTarget`, `SetPathField` 와 같은 모양이다.
받는 쪽마다 `TryGetComponent` 로 반응을 찾는 안을 먼저 넣었다가 되돌렸다.
**같은 네 줄이 `Boss` 와 `SplitOnDeath` 에 두 번 들어가고, 그 두 곳의 기존 줄과 모양이 어긋났다.**
`EnemyBase` 가 연출을 알게 된다는 것이 버린 근거였는데, `SetColor` 로 이미 색을 만지고 있어 서지 않았다.

### 세기는 맞는 쪽이 들고 있다

플레이어가 맞을 때와 적이 맞을 때의 세기가 다르다. 이벤트에 피해량을 싣지 않고
**각자 자기 컴포넌트에 자기 세기를 들고 있다.**

### 색의 소유자를 하나로 만든다

`EnemyBase` 가 `_renderer.color` 를 직접 칠하고 있었다. 번쩍임이 같은 값을 만지면 둘이 서로를 덮는다.
`SetColor` 는 상태가 바뀔 때만 불리므로, 번쩍임이 칠한 색이 상태가 바뀔 때까지 남는다.

**`HitReaction` 이 색을 혼자 소유하고 `EnemyBase.SetColor` 는 그쪽으로 넘긴다.**
`HitReaction` 은 지금의 상태 색을 `_baseColor` 에 따로 기억한다.

| 상황 | 일어나는 일 |
|---|---|
| 번쩍이는 중에 상태가 바뀐다 | `_baseColor` 만 갱신하고 화면은 그대로. 끝나면 **새 상태 색**으로 |
| 번쩍이지 않을 때 상태가 바뀐다 | 기억과 화면을 함께 바꾼다 |

**`EnemyBase._renderer` 는 이 변경으로 안 쓰이게 되어 지웠다.**

`HitReaction` 은 `SpriteRenderer` 를 프로퍼티로 지연 초기화한다.
**같은 오브젝트의 `Awake` 순서가 보장되지 않아**, `EnemyBase.Awake` 의 `ChangePhase(Idle)` 가
`HitReaction.Awake` 보다 먼저 색을 넣는 경우가 있다. 어느 순서로 돌아도 같은 결과로 끝난다.

### 겹침을 같은 규칙으로 다룬다

반응 셋이 한 순간에 여러 번 일어날 수 있다. **빈도가 세기를 바꾸지 않아야 한다.**

| 반응 | 겹칠 때 | 어디서 정했나 |
|---|---|---|
| 히트스톱 | 긴 쪽만 | 우리 코드의 `Mathf.Max` |
| 셰이크 | 가장 센 것만 | 패키지 설정 `Signal Combination Mode = Use Largest` |
| 플래시 | 겹치지 않는다 | 대상마다 자기 색이라 겹칠 일이 없다 |

셰이크의 기본값은 `Additive` 였다. 임펄스가 0.2초 사는데 활이 0.15초마다 쏘므로
**평균 1.33개가 함께 살아 더해졌다.** 연사 아이템을 집으면 같은 값을 넣어 두고도 화면이 더 흔들린다.
`Use Largest` 가 히트스톱의 `Mathf.Max` 와 같은 규칙이라 그쪽으로 맞췄다.

## 검증

**EditMode 테스트: 해당 없음.**
순수 계산은 '겹치면 긴 쪽을 남긴다' 한 줄(`Mathf.Max`)뿐이고 나머지는 전부
`Time`, `SpriteRenderer`, Cinemachine 에 의존한다. 한 줄을 `Logic` 으로 빼는 것은 과설계다.

**플레이모드 체크리스트**

- [x] 적을 때리면 **그 적만** 번쩍인다. 옆의 적은 그대로다
- [x] 번쩍인 뒤 적의 색이 상태에 맞다 (쫓는 중 파랑, 대기 빨강, 근접 적의 초록)
- [x] 돌진 적의 예고(노랑) 중에 때리면 번쩍인 뒤 **노랑으로** 돌아온다
- [x] 번쩍이는 사이에 적이 쫓기 시작하면 번쩍인 뒤 **파랑으로** 돌아온다
- [x] 플레이어가 맞으면 시간이 멈추고 화면이 흔들린다
- [x] **시간이 멈춘 그 순간에도 화면이 흔들린다**
- [x] 창으로 여럿을 한 번에 때려도 멈춤이 **한 번**이다
- [x] 분열 적이 쪼개진 뒤 여럿을 연달아 때려도 시간이 길게 멈추지 않는다
- [x] 아이템을 집어 최대 체력이 늘 때 화면이 흔들리지 않는다
- [x] 보스의 페이즈 전환 무적 중에 때리면 아무 일도 없다
- [x] 대시 무적으로 적의 공격을 지나가면 아무 일도 없다
- [x] 방을 옮긴 뒤에도 흔들림이 그 방 카메라에서 보인다

## 계단

```
[x] 1. 히트스톱 - 플레이어가 맞을 때   Health.OnDamaged 를 만들고 씬 참조로 잇는다
[x] 2. 히트스톱 - 적이 맞을 때         생성되는 적에게 주입하는 길을 연다
[x] 3. 카메라 셰이크                   Cinemachine Impulse 를 쏜다
[x] 4. 피격 플래시                     색의 소유자를 HitReaction 으로 옮긴다
```

1과 2를 가른 것은 **주입 없이 확인되는 지점을 먼저 만들기 위해서다.**
플레이어는 씬에 있어 인스펙터로 잇는다. 적은 생성되므로 주입이 필요하다.

4를 마지막에 둔 것은 적의 색을 건드리는 유일한 계단이기 때문이다.
`EnemyBase` 는 계단 2에서도 고쳤다(주입 보관 7줄). **계단별 변경은 커밋 본문에 적었다.**
`HitReaction` 과 씬, 프리팹에 네 계단의 변경이 섞여 파일 단위로 커밋을 가를 수 없었다.

## 메모

**착수 전에 코드에서 확인한 것 다섯.**

| 확인한 것 | 어디 |
|---|---|
| `OnHealthChanged` 가 피격과 최대 체력 변경을 섞는다 | `Health.cs:81`, `PlayerStats.cs:50` |
| `Health` 가 이미 `SpriteRenderer` 를 쥐고 무적 동안 깜빡인다 | `Health.cs:43` |
| `SetColor` 는 상태가 바뀔 때만 불린다. 매 프레임이 아니다 | `EnemyBase.cs:239` |
| `AreaHit` 이 맞힌 수를 돌려주는데 `MeleeWeapon` 이 버린다 | `MeleeWeapon.cs:29` |
| `Projectile` 은 누가 쐈는지 모른다. 레이어로만 갈린다 | `Projectile.cs:33` |

**`timeScale` 을 0 으로 만들 때 같이 멈추는 것.**

```
멈춘다      FixedUpdate(물리), Time.deltaTime, WaitForSeconds, 무적 타이머
안 멈춘다   Update 호출 자체, Time.unscaledDeltaTime, WaitForSecondsRealtime
            Cinemachine Impulse (IgnoreTimeScale 을 켠 경우)
```

마지막 줄은 패키지 소스를 읽고 적었다.
`CinemachineImpulseManager.cs:452` 에 `IgnoreTimeScale` 이 있고
458줄이 `CurrentTime => IgnoreTimeScale ? Time.realtimeSinceStartup : CinemachineCore.CurrentTime` 이다.

**방마다 `CinemachineCamera` 가 있고 방 프리팹은 하나다.**
Impulse Listener 를 프리팹에 한 번 붙이면 모든 방에 적용된다.

**`RequireComponent` 는 기존 오브젝트에 소급 적용되지 않는다.** 확인됐다.
`HitReaction` 에 `CinemachineImpulseSource` 요구를 더했는데, 이미 `HitReaction` 이 붙어 있던
적 프리팹 여섯에 따라오지 않아 하나씩 직접 붙였다. 새로 붙이는 컴포넌트에만 작용한다.

**히트스톱은 연사와 곱해진다.** 멈춘 시간의 비율은 초당 공격 횟수 곱하기 멈춤 시간이다.

| 무기 | 초당 공격 | 0.01 일 때 | 0.05 였다면 |
|---|---|---|---|
| 활 | 6.67 | 6.7% | 33.4% |
| 창 | 2.5 | 2.5% | 12.5% |
| 검 | 1.2 | 1.2% | 6.0% |

아이템의 `AttackSpeed` 퍼센트 모디파이어를 에셋에서 전부 더하니 **+60%** 였다
(효과와 시너지 전부, `GreatSword` 의 -10% 포함). 가방 5 곱하기 5 에 다 들어가지는 않지만
활 기준으로 초당 10발 가까이는 나온다.

**보스에 0.05 를 주려던 것을 이 계산으로 되돌렸다.** 보스는 가장 오래 계속 맞는 대상이라
멈춤이 길면 보스전 전체가 느려진다. 묵직함은 셰이크로 옮겼다(적의 두 배).

**정한 값.** 한 판 보고 한 번 정했다.

| 대상 | Hit Stop Time | Shake Force | Flash Time | Flash Color |
|---|---|---|---|---|
| 플레이어 | 0.08 | 0.3 | 0.1 | 흰색 |
| 적 다섯 | 0.01 | 0.1 | 0.1 | 흰색 |
| 보스 | 0.01 | 0.2 | 0.1 | 흰색 |

**셰이크와 플래시는 멈춘 시간을 서로 반대로 다룬다.**
셰이크는 `IgnoreTimeScale` 로 흘러가고 플래시는 `Time.deltaTime` 으로 멈춘다.
플래시가 흘러가면 플레이어의 멈춤(0.08) 사이에 번쩍임(0.1)이 거의 끝나 눈에 보이지 않는다.
**셰이크는 움직임이라 멈춘 동안 흘러야 보이고, 플래시는 상태라 멈춘 동안 유지돼야 보인다.**
