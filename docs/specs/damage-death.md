# 피격과 사망

## 왜 필요한가

**지금까지 미뤄둔 것들이 여기서 만난다.**

- 투사체가 적에 닿아도 아무 일이 없다
- 적의 공격이 `Debug.Log` 로만 남아 있다
- `PlayerMotor.IsDashing` 을 아무도 읽지 않는다

이 셋을 잇는 명세다. 이걸로 **전투가 성립하고 승패가 생긴다.**

여기서 만드는 구조는 프로젝트 끝까지 쓴다. 적이 4종으로 늘고 보스가 생겨도
이 뼈대 위에 얹힌다.

## 구조

**`IDamageable` 인터페이스와 `Health` 컴포넌트 둘로 만든다.**

```
투사체 ─┐
        ├─▶  IDamageable.TakeDamage(피해량)  ◀─  Health 가 구현
적 공격 ─┘
                                                   │
                                   플레이어와 적이 각각 Health 를 붙인다
```

**데미지를 주는 쪽은 상대가 무엇인지 모른다.** `IDamageable` 이면 그만이다.
적이 4종으로 늘어도, 파괴 가능한 상자가 생겨도 투사체 코드는 바뀌지 않는다.

**체력 처리는 한 곳에만 있다.** 감소, 사망 판정, 피격 후 무적은 적과
플레이어가 똑같다. 컴포넌트로 빼서 양쪽에 붙인다.

## 동작 정의

**피해를 주는 쪽**
- 투사체는 닿은 대상이 `IDamageable` 이면 피해를 주고 사라진다.
- 대상이 `IDamageable` 이 아니면(벽 등) 피해 없이 사라진다. 지금과 같다.
- 적은 `Attack` 상태에서 쿨다운마다 플레이어에게 피해를 준다.
  지금 `Debug.Log` 자리가 실제 공격이 된다.

**피해를 받는 쪽**
- 체력이 피해량만큼 준다.
- 체력이 0 이하가 되면 죽는다.
- **피격 직후 짧은 시간 동안 다시 피해를 받지 않는다.**
  적의 공격은 쿨다운을 돌지만 **적마다 따로 돈다.** 셋에게 둘러싸이면
  초당 세 대를 맞아 체력 5가 2초를 못 버틴다. 맞고 나서 빠져나갈 여유가 없다.
  (구현 중 직접 플레이해 확인한 근거다. 처음에는 "매 프레임 피해를 받는다"고
  적었으나, 접촉 피해를 뺐고 적 공격에 쿨다운이 있으므로 사실이 아니었다.)
- 무적인 동안 **눈에 보이는 표시가 있다.** 도형이므로 깜빡임으로 한다.
- 죽은 뒤에는 더 이상 피해를 받지 않는다.

**대시 무적**
- 플레이어는 **대시 중에도 피해를 받지 않는다.**
- 이동 명세가 `IsDashing` 으로 상태만 노출해 뒀다. 그것을 여기서 읽는다.
- 즉 무적 사유가 둘이다. **피격 후 무적**과 **대시 중 무적**이다.

**죽으면**
- 적은 사라진다.
- 플레이어는 **죽은 상태가 되고 움직이지 않는다.** 조작을 받지 않는다.
  게임오버 화면과 재시작은 이 명세가 만들지 않는다.

## 경계: 이 기능이 하지 않는 것

- **게임오버 화면, 재시작** → 씬 흐름 명세. 여기서는 죽은 상태까지만 만든다.
- **HP UI** → 별도. 지금은 로그로 확인한다.
  ROADMAP Phase 2의 HP UI 항목은 이 명세 다음이다.
- **넉백, 피격 경직** → Phase 5 폴리싱
- **적과 접촉만으로 받는 피해** → 적의 공격만 피해를 준다.
- **사망 연출, 파티클** → Phase 5
- **적 전용 레이어** → 필요 없다. 투사체는 이미 플레이어와 충돌하지 않으므로
  `IDamageable` 검사만으로 대상이 갈린다.
  적이 투사체를 쏘게 되면 그때 다시 본다.
- **피해량에 영향을 주는 스탯과 버프** → Phase 3 스탯 시스템

## 초기 수치

플레이하면서 조정한다. 시작점이다.

| 값 | 초기값 |
|---|---|
| 플레이어 최대 체력 | 5 |
| 적 최대 체력 | 3 |
| 투사체 피해량 | 1 |
| 적 공격 피해량 | 1 |
| 피격 후 무적 시간 | 플레이어 0.5초, **적 0초** |

적을 세 발에 잡고, 플레이어는 다섯 대를 버틴다.

**적의 무적 시간은 0이다.** 같은 `Health` 컴포넌트를 쓰되 값으로 구분한다.
적에게 무적을 주면 연사가 대부분 무시된다. 발사 간격이 0.15초인데
무적이 0.5초면 세 발 중 한 발만 들어간다.

## 검증

**EditMode 테스트**: 해당 없음.

체력 감소와 사망 판정은 순수 로직이라 뺄 수 있으나, MonoBehaviour 안에 둔다.
Phase 3에서 스탯 시스템을 만들 때 피해량 계산이 `JM2D.Logic` 으로 가고,
그때 테스트를 붙인다. **CLAUDE.md 5번이 EditMode 테스트 대상으로 지목한
"스탯 계산 및 모디파이어 중첩"이 그 작업이다.**

**플레이모드 체크리스트**

- [ ] 투사체가 적에 맞으면 적 체력이 준다
- [ ] 적 체력이 0이 되면 적이 사라진다
- [ ] 한 적이 죽어도 다른 적은 계속 동작한다
- [ ] 투사체가 벽에 맞으면 그냥 사라진다
- [ ] 적이 공격하면 플레이어 체력이 준다
- [ ] **피격 직후 짧은 시간 동안 다시 맞지 않는다**
- [ ] 무적인 동안 깜빡여서 눈에 보인다
- [ ] **대시 중에는 적 공격에 맞지 않는다**
- [ ] 플레이어 체력이 0이 되면 움직이지 않는다
- [ ] 죽은 뒤에는 더 이상 피해를 받지 않는다

> 여섯 번째를 빼면 여러 적에게 둘러싸였을 때 손쓸 여유가 없다.
> 여덟 번째가 이동 명세에서 노출만 해 둔 `IsDashing` 을 처음 쓰는 지점이다.

## 메모

**대시 무적을 `Health` 에 어떻게 연결할지는 구현 단계에서 정한다.**
`Health` 가 `PlayerMotor` 를 직접 알게 하면 적에게도 딸려오므로 피하고 싶다.
명세는 관찰 가능한 동작만 정의하고, 배선은 만들면서 가장 단순한 방법을 고른다.

**투사체가 피해량을 직접 갖는다. 이것은 공격력 스탯이 생기면 바뀐다.**

지금은 `_damage` 가 투사체 프리팹에 박혀 있어 누가 쏘든 값이 같다.
공격력 스탯이 들어오면 발사자의 공격력을 반영하지 못한다.

지금 고치지 않는 이유는 **넘길 값이 없기 때문**이다. `Launch(방향, 피해량)`
로 바꿔도 발사자가 하드코딩된 1을 넘기게 되어 자리만 옮기는 셈이 된다.

바꿀 시점은 **Phase 3의 스탯·모디파이어 시스템**이다. 그때 발사자가 자기
공격력을 계산해 넘기는 형태로 간다. 크리티컬, 속성, 출처 추적이 필요해지면
그다음에 `DamageInfo` 같은 구조체를 검토한다. feature-pool S급 3번이
스탯 시스템의 요구로 출처 추적을 적어 두었다.

피해량을 `int` 로 둔다. 스탯 시스템에서 곱연산이 들어오면 소수 처리가
필요해질 수 있으나, 지금 `float` 로 두면 체력 표시가 지저분해진다.
필요해지면 그때 바꾼다.
