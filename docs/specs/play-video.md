# 플레이 영상

## 왜 필요한가

**포트폴리오 때문이다.** 서류에서 면접관이 보는 첫 관문이고, 여러 자료가 공통으로
'플레이 가능한 것을 보여 달라' 를 1순위로 꼽았다. 결정 문서 41개는 면접에 들어간 뒤의
무기이고, 서류를 통과시키는 것은 영상과 README 다.

## 녹화 방식

```
도구        Unity Recorder (에디터 전용 패키지. 빌드에 들어가지 않는다)
해상도      1920 x 1080 또는 1600 x 900
오디오      Recorder 가 담는다 (시험 녹화로 확인했다)
방식        필요한 구간만 따로 찍어 편집으로 이어 붙인다
```

**BGM 은 녹화에서 빼고 편집에서 한 트랙으로 깐다.** 구간을 이어 붙이면 음악이 끊기기
때문이다. 녹화 전에 씬의 `Bgm` 오브젝트를 끄면 효과음만 담긴다.
음악이 도는 씬은 `Gameplay` 뿐이고 마을과 타이틀은 원래 무음이라, 한 트랙을 처음부터
끝까지 깔아야 한다. BGM 은 CC BY 4.0 이라 **영상 설명란에도 출처를 적는다**(지금은 README 에만 있다).

## 구성 (1분 27초 기준)

**길이를 정하고 채우지 않는다.** 구간마다 '이 초가 무엇을 증명하나' 를 묻고 답이 없으면
자른다. 보여줄 그림이 약해서, 길어지면 기능이 아니라 **같은 방에서 같은 적을 더 오래
때리는 화면**이 늘어난다. 처음 2분 55초로 잡았던 것을 그 기준으로 두 번 깎았다.

**깎는 순서를 정해 두었다. 가방이 마지막이다.** 전투와 진행을 먼저 깎고 가방은 거의
건드리지 않는다. 읽는 데 시간이 걸리는 유일한 기능이라, 짧게 자르면 '평범한 탑다운 슈터에
인벤토리가 붙은 것' 으로 보인다. 전투와 진행에서 35초를 걷고 가방은 5초만 줄였다.

**여는 하이라이트 8초는 녹화하고 나서 뺐다.** 보스 2페이즈 전환 하나만 걸려던 자리인데,
찍어 놓고 보니 1:05 의 보스 구간과 같은 화면이었다. 1분 27초 안에서 같은 장면을 두 번
보이는 것은 '이것밖에 없다' 로 읽힌다. 그 역할은 README 의 GIF 가 대신한다.
**짧은 영상에는 예고편이 필요 없다.** 본편까지 1분이 남지 않는다.

```
0:00 - 0:10   마을
              검을 들고 시작, 무기대 셋(잠긴 자리는 어둡다), 입구로 입장
              잠긴 무기대는 마지막 구간의 해금과 짝이라 남긴다
              자막: "마을에서 무기를 고르고 던전으로"

0:10 - 0:25   전투
              적 조합 한 번, 대시 회피 한 번, 문이 닫히고 열리는 것 한 번
              가장 많이 깎은 구간이다. 한 번씩 보이면 끝이다
              자막: "적 4종 + 보스 1기 / 공통 부모와 상태 머신"

0:25 - 0:55   가방 (차별화 지점. 거의 깎지 않는다)
              보상 창에서 고르기, 가방을 열어 배치, 스탯이 바뀌는 것, 시너지가 붙는 것
              자막: "아이템을 어디에 놓느냐로 빌드가 갈린다"
              자막: "배치 유효성과 시너지 탐색은 유닛테스트 대상"

0:55 - 1:05   진행
              방 카운터가 올라가는 것, 장애물 사이로 적이 돌아오는 것
              자막: "절차적 방 배치 / BFS 흐름장 길찾기"

1:05 - 1:20   보스
              커지며 등장, 시야가 넓어지는 것, 패턴 둘, 2페이즈 전환, 격파
              전환에서 몸이 보라색이 되고 화면이 끊어서 세 번 흔들린다
              자막: "패턴 넷을 거리로 고른다 / 2페이즈는 값 묶음을 갈아 끼운다"

1:20 - 1:27   복귀
              결과 창(기록과 '새 무기가 열렸습니다'), 마을의 기록판과 밝아진 무기대
              자막: "기록으로 무기가 열린다"
```

**0:25 부터의 30초가 핵심이다.** GDD 가 가방 배치를 차별화 지점으로 꼽았고,
영상에서 가장 설명이 필요한 부분이다.

**자막을 넣는 이유**는 프로그래머 영상이기 때문이다. 여러 자료가 '구현한 기능과 특별한
점을 짚어 주는 방식' 을 권했다. 무엇을 만들었는지가 보여야 한다.

## README 에 넣을 GIF

**그림이 약할 때는 3초 반복 하나가 30초 영상보다 낫다.** 영상을 짧게 가져가는 대신
README 에 짧은 GIF 를 둘셋 넣는다. 같은 녹화본에서 자르므로 추가 비용이 거의 없다.
영상에서 뺀 여는 하이라이트의 역할도 여기로 옮겼다. GIF 는 저절로 반복되므로
한 번 보이고 지나가는 영상 머리보다 전환을 보이기에 낫다.

```
가방에 아이템을 끼우고 스탯이 바뀌는 순간
보스의 2페이즈 전환
적이 장애물을 돌아 쫓아오는 것
```

## 녹화 전 점검

```
[ ] 저장 파일을 지운다 (JM2D > 저장 파일 > 저장 파일 지우기)
      처음 켠 사람이 보는 흐름을 찍는다. 잠긴 무기대와 '아직 없습니다' 기록판이 보인다
      그 뒤 한 판을 끝내면 해금 장면까지 이어진다
[ ] Game 뷰 비율을 16 대 9 로 고정한다
      비율이 넓으면 카메라가 방 밖을 비춘다
[ ] 숫자 키 1 2 3 을 누르지 않는다
      에디터에만 있는 무기 교체 뒷문이다. 빌드에는 없다
[ ] Bgm 오브젝트를 끈다
[ ] _debugRoomCount 가 0 인지 본다
      3 인 채로 커밋되고 빌드까지 간 적이 있다. 방이 8개여야 '방 5 / 8' 을 찍을 수 있다
[ ] 마이크와 알림을 끈다
[ ] 손에 익을 때까지 연습한다
      영상에 보이는 플레이도 평가 대상이다. 특히 보스 패턴 회피와 대시
```

## 방이 같아 보이는 것을 피하는 법

**방 프리팹이 하나라 여덟 방의 바닥과 벽이 같다.** 장애물 자리만 달라진다.
영상에서 이것이 '같은 방을 여덟 번 돈다' 로 읽히지 않게 한다.

```
방을 순서대로 보여주지 않는다
2번, 5번, 7번처럼 골라 찍고 적 조합과 무기를 다르게 한다
여러 판을 찍어 좋은 것만 고른다 (시드마다 배치가 달라진다)
```

## 경계 — 이 작업이 하지 않는 것

- **게임을 고치지 않는다.** 녹화하다 눈에 걸리는 것이 나오면 적어 두고 영상을 먼저 끝낸다
  - 예외는 **영상이 증명해야 하는 것**이다. 보스 2페이즈 전환이 화면에서 구분되지 않던 것을
    여기서 고쳤다. 자막이 그것을 주장하는데 화면에 없으면 근거 없는 말이 된다
- 적 사망 연출, 문 스프라이트, 볼륨 조절은 쌓아 둔 그대로다
- 영상 하나와 GIF 둘셋만 만든다. 다른 길이의 버전은 필요해지면 그때 자른다
