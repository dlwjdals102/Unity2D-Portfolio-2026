# 플레이어 공격

## 왜 필요한가

수직 슬라이스의 두 번째 조각. 이동만으로는 코어 루프가 돌지 않는다.
적을 만들기 전에 공격이 먼저 있어야 적이 죽는 것을 확인할 수 있다.

GDD 1번이 조작의 정체성을 **수동 조준 + 대시 회피**로 정의했다.
이동 명세가 회피를 담당했고, 이 명세가 조준을 담당한다.

## 동작 정의

**조준**
- 조준 방향은 플레이어에서 **마우스 커서를 향하는 방향**이다.
- 조준은 이동과 독립이다. 왼쪽으로 걸으면서 오른쪽을 쏠 수 있다.

**발사**
- 마우스 왼쪽 버튼을 누르면 조준 방향으로 투사체가 나간다.
- 버튼을 누르고 있으면 연사 간격마다 계속 나간다.
- 연사 간격이 지나지 않았으면 눌러도 나가지 않는다.

**투사체**
- 발사 지점은 플레이어의 위치다.
- 일정한 속도로 조준 방향을 향해 직진한다. 중력을 받지 않는다.
- **벽에 맞으면 사라진다.**
- 수명이 다하면 사라진다. 화면 밖으로 나간 투사체가 영원히 남지 않게 한다.
- 플레이어 자신과는 충돌하지 않는다.

**대시와의 관계**
- **대시 중에는 발사할 수 없다.** 회피와 공격을 동시에 하지 못하게 해서
  둘 중 하나를 고르는 선택이 생기게 한다.

## 경계 — 이 기능이 하지 않는 것

- **데미지 계산과 적중 판정** → 적 명세에서. 지금은 맞출 대상이 없다.
- **게임패드 조준** → 스틱으로 조준하려면 조준 방향을 보여주는 표시가 필요하다.
  마우스는 커서가 그 역할을 대신하므로 지금은 마우스만 만든다.
- **오브젝트 풀링** → Phase 3. 지금은 `Instantiate` 와 `Destroy` 로 둔다.
  **일부러 그렇게 두는 것이다.** 나중에 풀링으로 바꾸면서 프로파일러 수치를
  전후로 비교하기 위해서다. (feature-pool S급 1번)
- 무기 교체, 무기 종류 확장 → Phase 4
- 탄약, 재장전
- 반동, 화면 흔들림, 발사 이펙트 → Phase 5 폴리싱
- 차지 공격, 관통, 튕김

## 검증

**EditMode 테스트** — 해당 없음.
조준 계산이 카메라에 의존하고 투사체는 물리에 의존하므로
CLAUDE.md 5번의 테스트 대상이 아니다.

**플레이모드 체크리스트**

- [ ] 마우스 커서 방향으로 투사체가 나간다
- [ ] 플레이어를 움직여도 조준 방향이 커서를 따라온다
- [ ] 왼쪽으로 이동하면서 오른쪽으로 쏠 수 있다
- [ ] 버튼을 누르고 있으면 일정 간격으로 연사된다
- [ ] 연사 간격보다 빠르게 클릭해도 간격이 지켜진다
- [ ] 투사체가 벽에 맞으면 사라진다
- [ ] 투사체가 플레이어를 통과한다 (자기 총에 막히지 않는다)
- [ ] 아무것도 맞지 않은 투사체가 일정 시간 뒤 사라진다
- [ ] 대시 중에는 발사되지 않는다
- [ ] 오래 쏘고 나서 Hierarchy에 투사체가 쌓여 있지 않다

> 마지막 항목이 중요하다. 수명 처리를 빠뜨리면 눈에 안 보이는 곳에
> 오브젝트가 무한히 쌓인다. Phase 3에서 풀링을 도입할 때 비교할 기준선이기도 하다.

## 메모

투사체 수명과 연사 간격의 초기값은 플레이하면서 정한다.
적이 없는 상태에서 정한 값이므로 적이 생기면 다시 볼 가능성이 높다.

`Instantiate` 와 `Destroy` 를 쓰는 것은 CLAUDE.md 6번(매 프레임 생성·파괴 금지)에
어긋나 보이지만, **Phase 3에서 풀링으로 교체하는 것을 전제로 한 의도된 선택**이다.
전후 수치를 비교할 대상이 있어야 최적화가 증거가 된다.
