# 플레이어 이동 및 대시

## 왜 필요한가

수직 슬라이스의 첫 조각. 조작이 없으면 아무것도 검증할 수 없다.

**대시를 이동과 한 명세로 묶은 이유**는 대시가 이동의 한 상태이기 때문이다.
나중에 끼워 넣으면 이동 코드를 다시 쓰게 된다.
또 GDD 1번이 "수동 조준 + 대시 회피"를 조작의 정체성으로 정의했다.

## 동작 정의

관찰 가능한 동작으로만 적는다. 구현 방법은 여기 적지 않는다.

**이동**
- 8방향 자유 이동. 대각선이 직선보다 빠르지 않다.
- 입력에 즉시 반응한다. 키를 떼면 아주 짧게 미끄러지고 멈춘다.
- 벽을 통과하지 못한다. 벽에 비스듬히 밀면 벽을 따라 미끄러진다.

**대시**
- 대시 키를 누르면 **현재 이동 입력 방향으로** 짧고 빠르게 이동한다.
- 이동 입력이 없으면 **마지막으로 움직인 방향**으로 대시한다.
- 대시 중에는 이동 입력을 받지 않는다.
- 대시 중에는 **피격 판정을 받지 않는다(무적).**
- 대시가 끝나면 쿨다운이 돌고, 그동안 다시 대시할 수 없다.
- 대시 중 벽에 부딪히면 벽에서 멈춘다. 통과하지 않는다.

**선입력 버퍼**
- 쿨다운이 끝나기 **직전에** 누른 대시 입력은 버려지지 않는다.
  버퍼 시간 안이면 쿨다운이 끝나는 즉시 발동한다.

> 이 항목이 feature-pool S급 4번(게임필)의 첫 적용이다.
> 없어도 게임은 돌아가지만, 있고 없고가 조작감을 가장 크게 가른다.

## 경계 — 이 기능이 하지 않는 것

- 조준 / 공격 → 별도 명세
- 넉백, 피격 경직 → 피격 명세
- 애니메이션 → 도형이므로 없음
- 대시 잔상·파티클 → Phase 5 폴리싱
- 대시 횟수 스택, 대시 강화 아이템 → Phase 3 이후
- 이동 속도에 영향을 주는 버프/디버프 → 스탯 시스템(Phase 3)

## 검증

**EditMode 테스트** — 해당 없음.
이동은 MonoBehaviour와 물리에 의존하므로 CLAUDE.md 5번의 테스트 대상이 아니다.

**플레이모드 체크리스트**

- [ ] WASD 8방향으로 움직인다
- [ ] 대각선 이동이 직선보다 빠르지 않다
- [ ] 벽을 통과하지 못한다
- [ ] 벽에 비스듬히 밀면 벽을 따라 미끄러진다
- [ ] 대시가 이동 방향으로 나간다
- [ ] 정지 상태에서 대시하면 마지막 방향으로 나간다
- [ ] 대시 중 방향키를 꺾어도 방향이 안 바뀐다
- [ ] 대시 쿨다운 중에는 대시가 안 나간다
- [ ] 쿨다운 끝나기 직전에 누른 입력이 쿨다운 종료 직후 발동한다
- [ ] 대시로 벽에 박아도 벽을 뚫지 않는다
- [ ] 게임 오브젝트를 비활성화했다가 켜도 상태가 꼬이지 않는다
