# 추적 근접 적

## 왜 필요한가

수직 슬라이스의 세 번째 조각. 지금은 쏠 대상이 없어서 전투가 성립하지 않는다.

GDD 스코프의 적 4종(돌진 / 추적 근접 / 원거리 / 분열) 중 **추적 근접 하나만**
만든다. 가장 단순하고, 플레이어의 대시 회피가 의미를 갖는 상대이며,
나머지 셋의 기반이 된다.

**상태 머신이 처음 나오는 기능이다.** 면접에서 가장 깊게 파고드는 주제라
구조를 설명할 수 있게 만드는 것이 목적의 절반이다.

## 동작 정의

**상태 셋**

```
Idle  ──감지 범위 안──▶  Chase  ──공격 범위 안──▶  Attack
  ◀──추적 포기 범위 밖──          ◀──공격 범위 밖──
```

**Idle**
- 제자리에 멈춰 있다.
- 플레이어가 **감지 범위** 안에 들어오면 Chase로 간다.

**Chase**
- 플레이어 쪽으로 곧장 이동한다.
- **공격 범위** 안에 들어오면 Attack으로 간다.
- 플레이어가 **추적 포기 범위** 밖으로 나가면 Idle로 돌아간다.

**Attack**
- 제자리에서 공격 동작을 수행하고 쿨다운을 돈다.
- 공격 범위 밖으로 벗어나면 Chase로 돌아간다.

**범위는 셋이고, 감지와 추적 포기는 서로 다른 값이다.**

| 범위 | 뜻 |
|---|---|
| 감지 범위 | 이 안에 들어오면 추적을 **시작**한다 |
| 추적 포기 범위 | 이 밖으로 나가면 추적을 **멈춘다.** 감지 범위보다 넓다 |
| 공격 범위 | 이 안에서 공격한다 |

> **두 값을 같게 두면 경계에서 상태가 매 프레임 깜빡인다.**
> 플레이어가 경계에 서 있으면 Idle과 Chase를 오가며 적이 떨린다.
> 시작 조건과 종료 조건을 다르게 두어 그 사이에 여유를 만든다.

**상태 표시**
- 도형 프로토타입이라 애니메이션이 없으므로 **상태에 따라 색이 바뀐다.**
- 검증을 위한 것이다. 색을 보고 지금 어느 상태인지 알 수 있어야 한다.

## 경계: 이 기능이 하지 않는 것

- **체력, 데미지, 죽음** → 피격 명세에서. 지금은 맞아도 아무 일도 일어나지 않는다.
- **공격이 실제로 플레이어를 아프게 하는 것** → 피격 명세.
  여기서는 Attack 상태에 들어가고 쿨다운을 도는 것까지만 만든다.
- **경로 탐색** → 벽을 돌아가지 않는다. 플레이어 쪽으로 직진하다 벽에 막히면 막힌 채로 둔다.
  A*나 NavMesh는 Phase 2 스코프가 아니다.
- **시야 판정** → 벽 너머의 플레이어도 감지한다. 거리만 본다.
- 적 종류 확장 → Phase 4
- 적 스폰과 웨이브 → 방 명세
- 사망 연출, 피격 반응 → Phase 5

## 구현 방침

**`enum` + `switch`로 만든다.** 상태별 클래스로 나누지 않는다.

적 1종에 상태 3개면 `switch`가 충분히 읽힌다. 클래스로 나누면 파일이 늘고
흐름을 따라가려면 여러 곳을 오가야 한다. 지금 규모에서는 손해다.

**Phase 3에서 적이 4종으로 늘었을 때 실제로 불편해지면 그때 리팩터링한다.**
그 전후를 `docs/decisions/`에 남기면 "상태 패턴을 안다"가 아니라
**"언제 써야 하는지 안다"** 는 이야기가 된다. 후자가 훨씬 강하다.

## 검증

**EditMode 테스트**: 해당 없음.

상태 전이 판정은 순수 로직으로 뺄 수 있으나, 지금은 MonoBehaviour 안에 둔다.
Phase 3에서 FSM을 정리할 때 `JM2D.Logic` 으로 빼고 테스트를 붙일 후보다.
지금 빼면 적 1종을 위해 어셈블리 경계를 넘나드는 셈이라 이르다.

**플레이모드 체크리스트**

- [ ] 감지 범위 밖에서는 적이 움직이지 않는다
- [ ] 감지 범위 안에 들어가면 따라오기 시작한다
- [ ] 따라오는 동안 색이 바뀌어 상태가 구분된다
- [ ] 가까이 붙으면 공격 상태로 바뀐다
- [ ] 공격 상태에서 물러나면 다시 따라온다
- [ ] 멀리 도망가면 추적을 멈추고 제자리로 돌아간다
- [ ] **감지 범위 경계에 서 있어도 상태가 깜빡이지 않는다**
- [ ] 벽에 막히면 벽을 통과하지 않고 막힌 채로 있는다
- [ ] 적이 플레이어를 밀어내지 않는다 (또는 밀어내는 것이 자연스럽다)
- [ ] 투사체가 적에 맞으면 사라진다

> 일곱 번째가 감지 범위와 추적 포기 범위를 다르게 둔 이유를 검사한다.
> 두 값을 같게 만들어 보면 차이가 바로 보인다.

## 메모

범위 세 값과 이동 속도의 초기값은 플레이하면서 정한다.
적이 플레이어보다 느려야 도망칠 수 있고, 너무 느리면 위협이 되지 않는다.

**적은 별도 레이어를 만들지 않고 `Default` 에 둔다.** 지금 필요한 동작이
전부 기본 충돌 설정으로 되기 때문이다. 투사체는 벽과 적을 구분할 이유가 없고,
적이 벽과 플레이어에 부딪히는 것도 기본값으로 동작한다.

레이어가 필요해지는 시점은 **투사체가 적에게만 데미지를 줘야 할 때**,
즉 피격 명세다. 그때 만든다.
