# 씬 흐름과 HP UI

## 왜 필요한가

**Phase 2의 마지막 조각이다.** 이걸 끝내면 "시작 → 플레이 → 죽음 → 재시작"이
도는 게임이 된다. ROADMAP이 Phase 2의 목표로 잡은 상태다.

지금은 실행하면 곧바로 전투가 시작되고, 죽어도 아무 일이 없으며,
체력은 콘솔 로그로만 보인다. **게임의 틀이 없다.**

HP UI를 함께 만드는 이유는 **어차피 같은 UI 작업**이기 때문이다.
그리고 체력이 안 보이는데 갑자기 죽으면 플레이어가 납득하지 못한다.

## 구성

**씬은 둘이다.**

| 씬 | 역할 |
|---|---|
| `Title` | 시작 버튼 하나 |
| `Gameplay` | 전투. 결과 패널이 이 위에 뜬다 |

**게임오버와 클리어는 씬이 아니라 UI 패널이다.**

별도 씬으로 만들면 죽는 순간 전투 화면이 통째로 사라져서, 죽은 화면 위에
결과가 뜨는 흔한 연출을 못 한다. 씬 간 데이터 전달도 필요해진다.
코딩 규칙이 씬 간 데이터 전달에 static 남용을 금지하는데 그 문제를 만들 이유가 없다.

**결과 패널은 하나다.** 게임오버와 클리어는 **문구만 다르다.** 버튼 구성은 같다.

## 동작 정의

**타이틀**
- 게임을 실행하면 타이틀이 먼저 나온다.
- 시작 버튼을 누르면 `Gameplay` 로 간다.

**HP UI**
- 인게임에서 플레이어 체력이 **가로 바**로 항상 보인다.
- 체력이 변하면 즉시 반영된다.
- **매 프레임 값을 읽어 갱신하지 않는다.** 체력이 바뀔 때만 갱신한다.
  코딩 규칙이 UI를 이벤트로 갱신하도록 요구한다.

**결과 패널**
- 플레이어가 죽으면 패널이 뜨고 **게임 오버**라고 표시된다.
- 적을 전부 처치하면 패널이 뜨고 **클리어**라고 표시된다.
- 패널이 뜨면 **적이 더 이상 움직이지 않는다.**
- 버튼은 둘이다. **재시작**과 **타이틀로**.

**재시작**
- `Gameplay` 씬을 다시 로드한다.
- 체력, 적 배치, 남은 투사체, 쿨다운이 전부 처음 상태가 된다.

> 오브젝트를 하나씩 되돌리지 않는다. **반드시 빠뜨리는 것이 생기고**
> 이전 판의 흔적이 남는다. 씬을 다시 로드하면 전부 새로 만들어진다.
> 지금 규모에서 로딩은 순식간이다.

## 경계: 이 기능이 하지 않는 것

- **일시정지 메뉴** → 없다.
- **설정 화면, 볼륨 조절** → 없다.
- **점수, 처치 수, 런 기록** → feature-pool B급. Phase 5 이후.
- **메타 진행 저장** → GDD가 Phase 5로 잡았다. 지금 재시작은 완전 초기화다.
- **씬 전환 연출(페이드)** → Phase 5 폴리싱
- **종료 버튼** → Phase 6에서 빌드를 만들 때 넣는다. 에디터에서는 무의미하다.
- **절차적 방 생성** → Phase 4. 지금은 손으로 배치한 방 하나다.
- **적 스폰, 웨이브** → Phase 4. 씬에 미리 놓인 적이 전부다.

## 검증

**EditMode 테스트**: 해당 없음. 씬 로딩과 UI에 의존한다.

**플레이모드 체크리스트**

- [x] 실행하면 타이틀이 먼저 나온다
- [x] 시작 버튼으로 인게임에 들어간다
- [x] HP 바가 현재 체력을 보여준다
- [x] 맞으면 HP 바가 즉시 줄어든다
- [x] 죽으면 결과 패널이 뜨고 게임 오버라고 표시된다
- [x] **패널이 뜨면 적이 멈춘다**
- [x] 적을 전부 처치하면 결과 패널이 뜨고 클리어라고 표시된다
- [x] 재시작 버튼을 누르면 처음부터 다시 시작된다
- [x] **재시작 후 체력이 가득 차 있다**
- [x] **재시작 후 이전 판의 투사체나 죽은 적이 남아 있지 않다**
- [x] 타이틀로 버튼이 동작한다

> 아홉 번째와 열 번째가 씬을 다시 로드하기로 한 판단을 검사한다.
> 오브젝트를 손으로 되돌리는 방식이었다면 여기서 반드시 무언가 남는다.

## 완료 조건

- [x] 동작 정의를 전부 만족
- [x] 플레이모드 체크리스트 통과
- [x] 설계 판단이 있었다면 `docs/decisions/`에 기록
- [x] **임시 로그 둘을 지운다.** `Health` 의 체력 로그와 `PlayerDeath` 의 사망 로그.
  둘 다 이 기능이 대신하게 된다.

## 메모

`Health` 에 **체력이 바뀔 때 발생하는 이벤트**가 필요하다. 지금은 죽을 때만 알린다.
UI가 그 이벤트를 구독한다. feature-pool A급 7번(이벤트 기반 아키텍처)의 첫 적용이다.

**클리어 판정을 누가 할지는 구현 단계에서 정한다.** 적의 수를 세는 무언가가
필요한데, 매 프레임 세는 방식은 피하고 싶다.

**폰트 아틀라스는 `Dynamic` 으로 둔다.** 새 한글을 쓸 때 자동으로 추가되지만
에셋 파일이 커지고 커밋 diff 가 생긴다. `Static` 으로 굽고 쓰는 글자만
지정하면 파일이 작아지지만, 새 문구를 넣을 때마다 다시 구워야 하고
잊으면 글자가 조용히 안 나온다. 조용히 실패하는 쪽이 더 위험하다고 봤다.

두 씬 모두 **Build Settings에 등록**해야 씬 로딩이 동작한다.
빠뜨리면 실행 중에 씬을 못 찾는 오류가 난다.
