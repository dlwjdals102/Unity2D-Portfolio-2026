# 돌진 적 + FSM 재검토

## 왜 필요한가

**GDD 스코프의 적 4종 중 둘째다.** 추적 근접 적은 다가와서 붙어 있는 적이라
플레이어의 대시가 '빠져나가는' 데만 쓰였다. 돌진 적은 **예고를 보고 옆으로 비키는**
상대라, 대시가 회피로서 제 몫을 하게 된다.

**그리고 이 기능이 FSM 을 다시 볼 때다.** [추적 근접 적 명세](enemy-melee.md)가 이렇게 약속했다.

> 적이 4종으로 늘었을 때 실제로 불편해지면 그때 리팩터링한다.
> 그 전후를 남기면 '상태 패턴을 안다' 가 아니라 '언제 써야 하는지 안다' 는 이야기가 된다.

돌진 적은 상태가 가장 많이 늘고 기존 적과 나눠 쓸 것(대기, 추적)도 가장 많아
구조를 바꿀지 판단할 재료가 여기서 나온다.

## 동작 정의

### 상태

```
Idle ──감지 범위 안──▶ Chase ──돌진 범위 안──▶ Windup ──예고 시간──▶ Dash ──돌진 시간──▶ Recover
 ◀──추적 포기 범위 밖──                                                              │
                        ◀──────────────────────────── 회복 시간 ──────────────────────┘
```

**Idle, Chase**
- 추적 근접 적과 같다. 감지 범위와 추적 포기 범위를 다른 값으로 둔다.

**Windup (예고)**
- 멈춰 선다. **색이 바뀌어 곧 돌진한다는 것을 알린다.**
- **돌진 방향은 예고가 시작될 때 정해진다.** 이때의 플레이어 쪽을 향한다.
- 예고 시간이 지나면 Dash 로 간다. 그 사이 플레이어가 멀어져도 취소하지 않는다.

**Dash (돌진)**
- 정해 둔 방향으로 **플레이어보다 빠르게** 곧게 나아간다. 방향을 바꾸지 않는다.
- 돌진 중 플레이어와 닿으면 **한 번** 피해를 준다. 한 돌진에 두 번 주지 않는다.
- 돌진 시간이 지나면 Recover 로 간다. 벽에 막히면 막힌 채로 시간을 채운다.

**Recover (회복)**
- 멈춰 선다. 이 동안은 돌진하지 않는다.
- 회복 시간이 지나면 Chase 로 돌아간다. 가까우면 곧 다시 예고에 들어간다.

> **방향을 예고 시작에 정하는 이유.** 돌진 직전에 정하면 예고를 보고 비켜도
> 따라와 맞는다. 피할 수 없는 공격은 예고가 있어도 불공평하다.
> 방향이 먼저 정해져야 **예고를 읽고 비키는 것**이 성립한다.

> **상태가 깜빡일 걱정이 없는 이유.** [상태 전이 여유 값 결정](../decisions/state-transition-hysteresis.md)은
> '돌진 적은 순간적으로 플레이어보다 빠르므로 반드시 도달한다' 고 예고했다.
> 하지만 Windup, Dash, Recover 는 **시간으로 끝나는 상태**라 거리가 경계를 오가도
> 되돌아가지 않는다. 거리로 판정하는 곳은 Chase 에서 Windup 으로 들어가는 한 곳뿐이다.
> 이 판단이 맞는지는 플레이모드 체크리스트로 확인한다.

### 피해

- **돌진 중에만 닿으면 피해를 준다.** [피해 명세](damage-death.md)는 접촉 피해를 일부러 뺐다.
  돌진 적은 부딪히는 것이 공격이라, 접촉 피해를 **돌진 중에만** 연다.
- 대시 중인 플레이어는 맞지 않는다. 이미 `Health` 가 대시 무적을 처리한다.
- 돌진 적도 투사체에 맞으면 체력이 줄고 죽는다. 추적 근접 적과 같다.

### 상태 표시

- 추적 근접 적처럼 **상태마다 색이 다르다.** 특히 Windup 은 한눈에 구분돼야 한다.

## FSM 재검토: 어떻게 정하는가

**구조를 먼저 정하지 않는다.** 첫 계단에서 돌진 적의 상태를 지금 구조에 얹는 골격을
그려 보고, 무엇이 불편한지 확인한 뒤 고른다. 후보는 셋이다.

| 안 | 모양 |
|---|---|
| 가 | 지금처럼 `enum` 과 `switch`. 적 종류마다 컨트롤러를 따로 둔다 |
| 나 | 상태를 클래스로 나눈다(상태 패턴). 대기와 추적을 여러 적이 나눠 쓴다 |
| 다 | 전이 판정만 `JM2D.Logic` 으로 빼서 EditMode 테스트를 붙인다. 가, 나 와 함께 쓸 수 있다 |

**'불편하다' 를 느낌으로 두지 않는다.** 골격에서 무엇을 셀지 첫 계단에서 정한다.
예를 들어 같은 코드가 두 컨트롤러에 반복되는 줄 수, `switch` 한 칸의 길이,
새 상태 하나를 더할 때 고치는 곳의 수 같은 것이다.

## 경계: 이 기능이 하지 않는 것

- **원거리 적, 분열 적** → 다음 명세. 원거리는 적의 투사체와 편 가르기,
  분열은 런타임 생성과 적 수 세기를 끌고 온다.
- **적 풀링과 스폰** → 방과 웨이브 작업. 돌진 적은 씬에 놓는다.
- **경로 탐색, 시야** → 추적 근접 적과 같이 하지 않는다. 벽을 돌아가지 않는다.
- **돌진 궤적 표시** (바닥에 그리는 예고선) → 하지 않는다. 색으로만 알린다.
- **벽 충돌 반응** (튕김, 기절) → 하지 않는다. 막히면 시간을 채운다.
- **넉백** → 하지 않는다. 맞은 플레이어가 밀려나지 않는다.
- **밸런싱** → 하지 않는다. 예고와 회복 시간은 '피할 수 있다' 가 확인되는 데까지만 맞춘다.

## 검증

**EditMode 테스트**: 첫 계단의 구조 결정에 따른다.

전이 판정을 `JM2D.Logic` 으로 빼면(안 다) 전이 규칙을 테스트한다. 빼지 않으면 해당 없음이고,
그 이유를 결정 문서에 적는다.

**플레이모드 체크리스트**

- [x] 감지 범위 밖에서는 움직이지 않는다
- [x] 감지 범위 안에 들어가면 다가온다
- [x] 돌진 범위에 들어오면 멈추고 **예고 색**으로 바뀐다
- [x] 예고가 끝나면 **예고가 시작될 때의 방향**으로 곧게 돌진한다
- [x] **예고를 보고 옆으로 비키면 돌진이 빗나간다**
- [x] 돌진에 맞으면 피해를 한 번 받는다. 한 돌진에 두 번 받지 않는다
- [x] 대시로 돌진을 지나쳐 가면 피해를 받지 않는다
- [x] 돌진이 끝나면 잠시 멈춰 있다가 다시 다가온다
- [x] 멀리 도망가면 추적을 멈춘다
- [x] 돌진 범위 경계에서 오가도 **예고와 추적이 깜빡이지 않는다**
- [x] 돌진 적을 투사체로 죽일 수 있다
- [x] **추적 근접 적이 전과 똑같이 동작한다**
- [x] 두 적을 모두 죽이면 클리어가 뜬다

## 메모

**데이터 사본 필드를 여기서 판단한다.** 코드 리뷰에서 과설계로 봤다.
[데이터 소유 결정](../decisions/data-ownership.md)은 '버프를 곱할 자리' 라는 이유로
`Awake` 에서 값을 복사하게 했는데, 스탯 시스템은 `PlayerStats` 로 갔고 적의 사본은
한 번도 바뀌지 않는다. 돌진 적은 수치가 여섯 개 더 늘어 복사 줄도 그만큼 는다.
유지하든 걷어내든 그 결정을 새 결정 문서로 남기고 옛 문서에 `superseded_by` 를 단다.

**`EnemyData` 가 모든 적의 수치를 담을지도 정해야 한다.** 돌진 적은 예고 시간, 돌진 속도,
돌진 시간, 회복 시간, 돌진 범위, 돌진 피해가 필요하고 추적 근접 적은 필요 없다.
한 클래스에 다 넣으면 절반이 늘 비어 있는 에셋이 된다. 시너지 명세에서
`ItemModifier` 에 조건 필드를 넣지 않은 것과 같은 고민이다. FSM 구조와 함께 정한다.

**`EnemyCounter` 가 적을 `EnemyController` 타입으로 찾는다.** 돌진 적을 다른 클래스로
만들면 클리어 판정에서 빠진다. 체크리스트의 마지막 줄이 이것을 잡는다.

**적의 추적 대상은 씬에서 끌어다 놓은 참조다.** 돌진 적도 씬에 놓으니 지금은 괜찮다.
분열 적에서 문제가 된다.

**계단 1 결과: 공통 부모 + `switch` (가') 로 간다.**
부모가 대기, 추적, 체력 연결, 죽음 처리를 한 번만 갖고, 자식은 자기 공격만 `switch` 로 짠다.
부모의 상태는 대기, 추적, 교전 셋이고 교전 동안 자식의 `switch` 가 돈다.

적 넷(행동이 다른 것은 근접, 돌진, 원거리 셋)을 기준으로 골격을 그려 잰 결과다.

| | 반복되는 줄 | 구조가 만드는 줄 | 합 |
|---|---|---|---|
| 가. 종류마다 컨트롤러 | 94 | 27 | 121 |
| **가'. 공통 부모 + `switch`** | 0 | 74 | **74** |
| 나. 상태 패턴 | 0 | 129 | 129 |

분열이 컨트롤러를 따로 가져도, 원거리 상태가 셋이어도, 사본 필드를 걷어내도 가'가 가장 적었다.
상태 패턴은 상태마다 붙는 틀(필드, 생성자, 메서드 머리, 다음 상태 칸)이 반복을 없애는 값보다 컸다.
상태 클래스들의 부모를 두어 틀을 줄여도 100줄 안팎으로 어림돼 뒤집히지 않는다.

**거리 판정은 `JM2D.Logic` 의 함수 하나로 뺀다.** 대기 ↔ 추적(감지, 추적 포기)과 근접 적의
추적 ↔ 공격(공격, 공격 이탈)이 '들어가는 값과 나오는 값이 다른' 같은 모양이다.
테스트는 두 경계와 '두 값 사이에서는 지금 상태를 지킨다' 를 본다.

**나오는 값을 들어가는 값보다 작게 넣는 실수는 `EnemyData` 의 `OnValidate` 로 막는다.**
함수 테스트로는 잡히지 않는 데이터 실수라서다. 계단 2 에서 넣는다.

**계단 2 결과: 데이터는 부모와 자식으로 나눴다.** `EnemyData` 는 체력, 이동, 감지, 추적 포기만 갖는
추상 부모가 됐고 `MeleeEnemyData` 와 `DashEnemyData` 가 자기 공격 수치를 더한다.
컨트롤러의 가'와 같은 모양이라 둘이 짝을 이룬다. 한 클래스에 다 넣으면 적마다 절반이 빈 에셋이 된다.

기존 `EnemyData_Melee` 는 스크립트 참조만 `MeleeEnemyData` 로 바꿨고 값을 모두 지켰다.
Unity 가 에셋의 값을 필드 이름으로 찾기 때문이다. 시너지 명세에서 필드 이름을 바꿔 값을 잃은 것과 반대다.

**적의 사본 필드는 걷어내기로 했다.** 복사한 이유였던 '버프를 곱할 자리' 는 오지 않았고,
'데이터를 직접 고치는 유혹' 은 읽기 전용 프로퍼티가 이미 막는다. 걷어내면 플레이 중에 에셋 값을
고쳐도 바로 반영돼 계단 4 에서 수치를 맞추기 쉽다. 실제로 걷어내는 것은 계단 3 이다.
투사체의 사본은 이 명세 밖이라 원거리 적 명세에서 본다.

**나오는 값이 들어가는 값보다 작으면 경고한다.** 추적 포기 < 감지, 공격 이탈 < 공격 범위.
`EnemyController` 가 계단 3 전까지 컴파일되도록 `_data` 의 타입 이름만 `MeleeEnemyData` 로 바꿨다.

**계단 3 결과: 추적 근접 적을 `EnemyBase` 와 `MeleeEnemy` 로 나눴다.** 동작은 전과 같다.
`MeleeEnemy` 는 120줄에서 38줄이 됐다. 대기, 추적, 체력 연결, 죽음 처리가 부모로 가고
데이터 사본 필드 일곱과 복사 일곱 줄이 사라졌다. 거리 판정은 `Hysteresis.IsInside` 로 뺐고
EditMode 테스트 7개가 붙었다. 적 AI 에 붙은 첫 테스트다.

`EnemyController.cs` 는 `.meta` 와 함께 `MeleeEnemy.cs` 로 옮겨 GUID 를 지켰다.
프리팹과 씬을 하나도 고치지 않았고, `_data` 와 `_target` 값도 필드 이름으로 이어졌다.

**리뷰에서 버그 하나를 잡았다.** 공격을 멈추는 판정에 감지와 추적 포기 범위가 들어가,
적이 공격 상태에 머문 채 8칸 떨어진 플레이어까지 계속 때릴 뻔했다. 네 값이 모두 `float` 라
컴파일은 통과했다. 이름이 뜻을 충분히 말하지 않은 것이 원인이라 이름을 바꿨다.

| 옛 이름 | 새 이름 |
|---|---|
| `AttackRange` | `AttackStartRange`. 공격을 시작하는 거리이지 닿는 거리가 아니다. 실제로는 멈춤 거리까지 맞는다 |
| `AttackExitRange` | `AttackStopRange` |
| `DashRange` | `DashStartRange`. 예고를 시작하는 거리이지 돌진하는 거리가 아니다 |

근접 적 에셋은 `[FormerlySerializedAs]` 로 옛 값을 지켰다. 시너지 명세에서는 구조체가 한 겹
안으로 들어가 쓸 수 없었던 방법이다. 돌진 적 에셋은 커밋 전 새 파일이라 파일에서 바로 고쳤다.

**`ScriptableObjects` 를 종류별 폴더로 나눴다.** `Items`, `Enemies`, `Projectiles`.
`.meta` 와 짝으로 옮겨 GUID 가 그대로라 팔레트와 프리팹의 참조가 이어졌다.

**계단 4 결과: 돌진 적이 예고, 돌진, 회복을 한다.** `DashEnemy` 는 77줄이고 대기, 추적, 체력,
죽음 처리가 한 줄도 없다. 계단 1 에서 종류마다 컨트롤러를 두는 안으로 그린 골격은 102줄이었고
그중 47줄이 근접 적과 같은 일이었다. 부모에 `DirectionToTarget` 과 `Move` 두 도구를 더했다.

돌진 방향은 예고로 바뀔 때 정한다. 돌진 칸에서 매 스텝 구하면 유도가 되어 비킬 수 없고,
돌진으로 바뀔 때 구하면 비킨 자리로 날아와 예고가 쓸모없다.

플레이 중에 `EnemyData_Dash` 를 고치면 바로 반영된다. 사본 필드를 걷어낸 결과다.
다만 상태가 바뀔 때 읽는 시간 값은 다음 상태부터, 태어날 때 읽는 최대 체력은 이미 있는 적에
반영되지 않는다. ScriptableObject 의 값은 플레이를 멈춰도 남는다.

프리팹과 씬 배치를 계단 5 에서 계단 4 로 당겼다. 돌진 적이 움직이는 것을 보려면 씬에 있어야 한다.

**계단 5 결과: 돌진이 닿으면 한 번 피해를 준다.** 닿았는지는 거리로 본다.
근접 적도 거리로 때리므로 두 적이 같은 방식이 되고, 충돌 이벤트의 함정(이미 붙어 있는 상태로
돌진이 시작되면 닿는 순간이 없어 `OnCollisionEnter2D` 가 오지 않는다)을 피한다.

**접촉 반경의 기본값 1.0 은 틀린 값이었다.** 거리는 중심끼리 재므로 1×1 콜라이더 둘이
딱 붙어도 1.0 이고, 물리가 0.01 을 띄우므로 실제로는 1.01 이다. 서로 뚫지 못해 1.0 아래로
내려가지 않아 조건이 한 번도 참이 되지 않았다. 1.2 로 올려 고쳤다.
대각으로 스치면 중심 거리가 1.41 까지 벌어져 놓칠 수 있다. 거슬리면 가로와 세로를 따로 보는
사각 판정으로 바꾼다.

**한 돌진에 한 번만 맞힌다.** 피격 무적(0.5초)이 돌진 시간(0.35초)보다 길어 플래그가 없어도
결과는 같지만, 무적 시간을 줄이는 날 조용히 깨진다. 돌진의 규칙은 돌진이 지킨다.

**`EnemyCounter` 를 `EnemyBase` 로 찾게 바꿨다.** 적 종류가 늘어도 다시 고치지 않는다.

**물리로 밀리는 문제는 질량으로 완화했다.** 플레이어 질량을 20 으로 올려 돌진에 밀리지 않게 했다.
대신 플레이어가 적을 밀고 다니게 됐다. 질량 비율 하나로 두 방향을 같이 잡을 수 없어서,
레이어로 충돌을 끊을지는 원거리 적 명세에서 정한다. STATUS 의 열려 있는 질문에 올렸다.
