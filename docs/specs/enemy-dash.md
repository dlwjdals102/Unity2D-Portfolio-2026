# 돌진 적 + FSM 재검토

## 왜 필요한가

**GDD 스코프의 적 4종 중 둘째다.** 추적 근접 적은 다가와서 붙어 있는 적이라
플레이어의 대시가 '빠져나가는' 데만 쓰였다. 돌진 적은 **예고를 보고 옆으로 비키는**
상대라, 대시가 회피로서 제 몫을 하게 된다.

**그리고 이 기능이 FSM 을 다시 볼 때다.** [추적 근접 적 명세](enemy-melee.md)가 이렇게 약속했다.

> 적이 4종으로 늘었을 때 실제로 불편해지면 그때 리팩터링한다.
> 그 전후를 남기면 '상태 패턴을 안다' 가 아니라 '언제 써야 하는지 안다' 는 이야기가 된다.

돌진 적은 상태가 가장 많이 늘고 기존 적과 나눠 쓸 것(대기, 추적)도 가장 많아
구조를 바꿀지 판단할 재료가 여기서 나온다.

## 동작 정의

### 상태

```
Idle ──감지 범위 안──▶ Chase ──돌진 범위 안──▶ Windup ──예고 시간──▶ Dash ──돌진 시간──▶ Recover
 ◀──추적 포기 범위 밖──                                                              │
                        ◀──────────────────────────── 회복 시간 ──────────────────────┘
```

**Idle, Chase**
- 추적 근접 적과 같다. 감지 범위와 추적 포기 범위를 다른 값으로 둔다.

**Windup (예고)**
- 멈춰 선다. **색이 바뀌어 곧 돌진한다는 것을 알린다.**
- **돌진 방향은 예고가 시작될 때 정해진다.** 이때의 플레이어 쪽을 향한다.
- 예고 시간이 지나면 Dash 로 간다. 그 사이 플레이어가 멀어져도 취소하지 않는다.

**Dash (돌진)**
- 정해 둔 방향으로 **플레이어보다 빠르게** 곧게 나아간다. 방향을 바꾸지 않는다.
- 돌진 중 플레이어와 닿으면 **한 번** 피해를 준다. 한 돌진에 두 번 주지 않는다.
- 돌진 시간이 지나면 Recover 로 간다. 벽에 막히면 막힌 채로 시간을 채운다.

**Recover (회복)**
- 멈춰 선다. 이 동안은 돌진하지 않는다.
- 회복 시간이 지나면 Chase 로 돌아간다. 가까우면 곧 다시 예고에 들어간다.

> **방향을 예고 시작에 정하는 이유.** 돌진 직전에 정하면 예고를 보고 비켜도
> 따라와 맞는다. 피할 수 없는 공격은 예고가 있어도 불공평하다.
> 방향이 먼저 정해져야 **예고를 읽고 비키는 것**이 성립한다.

> **상태가 깜빡일 걱정이 없는 이유.** [상태 전이 여유 값 결정](../decisions/state-transition-hysteresis.md)은
> '돌진 적은 순간적으로 플레이어보다 빠르므로 반드시 도달한다' 고 예고했다.
> 하지만 Windup, Dash, Recover 는 **시간으로 끝나는 상태**라 거리가 경계를 오가도
> 되돌아가지 않는다. 거리로 판정하는 곳은 Chase 에서 Windup 으로 들어가는 한 곳뿐이다.
> 이 판단이 맞는지는 플레이모드 체크리스트로 확인한다.

### 피해

- **돌진 중에만 닿으면 피해를 준다.** [피해 명세](damage-death.md)는 접촉 피해를 일부러 뺐다.
  돌진 적은 부딪히는 것이 공격이라, 접촉 피해를 **돌진 중에만** 연다.
- 대시 중인 플레이어는 맞지 않는다. 이미 `Health` 가 대시 무적을 처리한다.
- 돌진 적도 투사체에 맞으면 체력이 줄고 죽는다. 추적 근접 적과 같다.

### 상태 표시

- 추적 근접 적처럼 **상태마다 색이 다르다.** 특히 Windup 은 한눈에 구분돼야 한다.

## FSM 재검토: 어떻게 정하는가

**구조를 먼저 정하지 않는다.** 첫 계단에서 돌진 적의 상태를 지금 구조에 얹는 골격을
그려 보고, 무엇이 불편한지 확인한 뒤 고른다. 후보는 셋이다.

| 안 | 모양 |
|---|---|
| 가 | 지금처럼 `enum` 과 `switch`. 적 종류마다 컨트롤러를 따로 둔다 |
| 나 | 상태를 클래스로 나눈다(상태 패턴). 대기와 추적을 여러 적이 나눠 쓴다 |
| 다 | 전이 판정만 `JM2D.Logic` 으로 빼서 EditMode 테스트를 붙인다. 가, 나 와 함께 쓸 수 있다 |

**'불편하다' 를 느낌으로 두지 않는다.** 골격에서 무엇을 셀지 첫 계단에서 정한다.
예를 들어 같은 코드가 두 컨트롤러에 반복되는 줄 수, `switch` 한 칸의 길이,
새 상태 하나를 더할 때 고치는 곳의 수 같은 것이다.

## 경계: 이 기능이 하지 않는 것

- **원거리 적, 분열 적** → 다음 명세. 원거리는 적의 투사체와 편 가르기,
  분열은 런타임 생성과 적 수 세기를 끌고 온다.
- **적 풀링과 스폰** → 방과 웨이브 작업. 돌진 적은 씬에 놓는다.
- **경로 탐색, 시야** → 추적 근접 적과 같이 하지 않는다. 벽을 돌아가지 않는다.
- **돌진 궤적 표시** (바닥에 그리는 예고선) → 하지 않는다. 색으로만 알린다.
- **벽 충돌 반응** (튕김, 기절) → 하지 않는다. 막히면 시간을 채운다.
- **넉백** → 하지 않는다. 맞은 플레이어가 밀려나지 않는다.
- **밸런싱** → 하지 않는다. 예고와 회복 시간은 '피할 수 있다' 가 확인되는 데까지만 맞춘다.

## 검증

**EditMode 테스트**: 첫 계단의 구조 결정에 따른다.

전이 판정을 `JM2D.Logic` 으로 빼면(안 다) 전이 규칙을 테스트한다. 빼지 않으면 해당 없음이고,
그 이유를 결정 문서에 적는다.

**플레이모드 체크리스트**

- [ ] 감지 범위 밖에서는 움직이지 않는다
- [ ] 감지 범위 안에 들어가면 다가온다
- [ ] 돌진 범위에 들어오면 멈추고 **예고 색**으로 바뀐다
- [ ] 예고가 끝나면 **예고가 시작될 때의 방향**으로 곧게 돌진한다
- [ ] **예고를 보고 옆으로 비키면 돌진이 빗나간다**
- [ ] 돌진에 맞으면 피해를 한 번 받는다. 한 돌진에 두 번 받지 않는다
- [ ] 대시로 돌진을 지나쳐 가면 피해를 받지 않는다
- [ ] 돌진이 끝나면 잠시 멈춰 있다가 다시 다가온다
- [ ] 멀리 도망가면 추적을 멈춘다
- [ ] 돌진 범위 경계에서 오가도 **예고와 추적이 깜빡이지 않는다**
- [ ] 돌진 적을 투사체로 죽일 수 있다
- [ ] **추적 근접 적이 전과 똑같이 동작한다**
- [ ] 두 적을 모두 죽이면 클리어가 뜬다

- [ ] 플레이모드 체크리스트 통과

## 메모

**데이터 사본 필드를 여기서 판단한다.** 코드 리뷰에서 과설계로 봤다.
[데이터 소유 결정](../decisions/data-ownership.md)은 '버프를 곱할 자리' 라는 이유로
`Awake` 에서 값을 복사하게 했는데, 스탯 시스템은 `PlayerStats` 로 갔고 적의 사본은
한 번도 바뀌지 않는다. 돌진 적은 수치가 여섯 개 더 늘어 복사 줄도 그만큼 는다.
유지하든 걷어내든 그 결정을 새 결정 문서로 남기고 옛 문서에 `superseded_by` 를 단다.

**`EnemyData` 가 모든 적의 수치를 담을지도 정해야 한다.** 돌진 적은 예고 시간, 돌진 속도,
돌진 시간, 회복 시간, 돌진 범위, 돌진 피해가 필요하고 추적 근접 적은 필요 없다.
한 클래스에 다 넣으면 절반이 늘 비어 있는 에셋이 된다. 시너지 명세에서
`ItemModifier` 에 조건 필드를 넣지 않은 것과 같은 고민이다. FSM 구조와 함께 정한다.

**`EnemyCounter` 가 적을 `EnemyController` 타입으로 찾는다.** 돌진 적을 다른 클래스로
만들면 클리어 판정에서 빠진다. 체크리스트의 마지막 줄이 이것을 잡는다.

**적의 추적 대상은 씬에서 끌어다 놓은 참조다.** 돌진 적도 씬에 놓으니 지금은 괜찮다.
분열 적에서 문제가 된다.
