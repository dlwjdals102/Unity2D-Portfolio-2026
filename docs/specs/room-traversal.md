# 방 잇기와 오가기 (4-B)

## 왜 필요한가

**4-A 가 만든 좌표 8개를 걸어 다닐 수 있는 방으로 바꾼다.** 지금은 좌표만 있고 게임은 여전히 방 하나다.
GDD 코어 루프의 '다음 방' 이 이 명세에서 처음으로 화면에 나온다.

기술적으로는 셋을 끌고 온다. **생성한 배치를 씬에 옮기는 일**, **플레이어가 지금 어느 방에 있는지 아는 일**,
**방보다 좁은 화면을 방에 맞춰 보여 주는 일**이다. 둘째는 4-C 의 '방에 들어가면 웨이브 시작' 이 그대로 쓴다.

## 정해진 것

명세를 쓰기 전에 합의했다. 근거는 4-B 를 마칠 때 결정 문서로 옮긴다.

- **방은 Tilemap 으로 만든다.** `2d.tilemap` 은 이미 설치돼 있다. 벽을 칸 단위로 칠하고 콜라이더를 하나로 합친다.
  타일 한 칸이 그대로 격자 한 칸이라, 방 안 장애물과 BFS 를 넣게 되면 바로 이어진다.
- **방 프리팹은 네 변 가운데에 문 구멍이 뚫려 있고, 구멍마다 문이 하나씩 있다.** 문 오브젝트가 켜져 있으면 닫힌 문이다.
  옆방과 이어진 변(`HasDoor` 가 참)은 문을 열고(끄고), 나머지는 닫아 둬 벽으로 쓴다. 4-C 에서 이어진 변의 문이 전투 중에 닫힌다.
- **4-B 는 방 프리팹 하나로 뚫는다.** GDD 의 '방 프리팹 8' 은 방 안 장애물을 판단할 때 함께 다시 본다.
  장애물이 방마다 무작위로 놓이면 모양이 다른 프리팹 여덟 개가 필요 없을 수 있다.
- **카메라는 Cinemachine 으로 플레이어를 따라가되 지금 방의 경계 안에 가둔다(엔터 더 건전 방식).**
  직접 작성하면 30 줄 안팎이지만, Unity 에서 카메라를 다룰 때 사실상 표준으로 쓰는 도구라 **그 도구를 잘 쓰는 법을 보여 주는 쪽**을 골랐다.
  경계 가두기(`CinemachineConfiner2D`)와 카메라 사이 블렌드가 들어 있고, Phase 5 카메라 흔들림(Impulse)도 같은 도구로 한다.
  **패키지 추가라 설치는 에디터의 Package Manager 에서 한다.**
- **씬에 손으로 놓은 적 넷을 뺀다. 클리어는 임시로 '보스 방에 들어가면' 이다.** 방이 여덟이 되면 시작 방의 적만 잡아도 끝나는 지금 조건이 어색하다.
  4-C 에서 웨이브와 보스 방 전투로 바꾼다.
- **'플레이어가 방에 들어갔다' 를 알린다.** 카메라 경계, 임시 클리어, 4-C 의 웨이브가 함께 쓴다.
- **시드는 판마다 무작위이고, 인스펙터에서 고정 시드를 켤 수 있다.** 이번 판의 시드는 인스펙터 필드에 남긴다. 로그로 찍지 않는다.
- (4-A 에서 정함) 방 8개를 한 씬에 모두 놓고 걸어서 오간다. 위치는 칸 좌표에 방 크기를 곱한 값이다.

## 동작 정의

### 방

- 게임이 시작되면 **방 8개가 한 씬에 놓이고**, 플레이어는 시작 방 가운데에 선다.
- **순번이 이어진 두 방 사이의 문은 열려 있어 걸어서 지나간다.** 문이 없는 변은 막혀 있다. U자로 붙은 두 방 사이도 막혀 있다.
- **플레이어는 방 밖(방이 없는 곳)으로 나갈 수 없다.**
- 시작 방, 전투 방, 보스 방은 **바닥 색으로 구분된다.** 도형 프로토타입의 '색으로 역할 구분' 이다.

### 카메라

- 카메라가 플레이어를 따라간다.
- **지금 방의 바깥을 비추지 않는다.** 방 모서리에 가면 카메라가 멈추고 플레이어만 움직인다.
- 문을 지나 다른 방에 들어가면 **카메라가 새 방의 경계를 따른다.** 옆방으로 넘어가는 모양(순간 전환, 블렌드)은 정할 것 3 에서 정한다.

### 판의 흐름

- **보스 방에 들어가면 클리어가 뜬다(임시).**
- 게임 오버, 다시 시작, 타이틀로 가기가 전과 같다.
- 고정 시드를 끄고 다시 시작하면 **다른 배치**가 나오고, 켜면 **같은 배치**가 나온다.

## 정할 것

**구조를 먼저 정하지 않는다.** 계단에서 대안을 견주고 정한 뒤 메모에 적는다.

### 1. 방 크기와 문 폭

'화면 두세 장 분량' 을 칸 수로 정한다. 카메라 정사영 크기 5 는 16:9 에서 가로 약 17.8, 세로 10 칸을 보인다.
플레이어가 대시로 지나가기 쉬운 문 폭도 함께 정한다. **만들어 걸어 보고 정한다.**

### 2. 지금 어느 방에 있는지 아는 방법

| 안 | 모양 | 따져 볼 것 |
|---|---|---|
| 가 | 방마다 트리거 콜라이더를 두고 플레이어가 들어오면 알린다 | Unity 에서 흔한 방식이다. 문턱에서 두 트리거에 동시에 걸치는 순간이 있다 |
| 나 | 플레이어 위치를 방 크기로 나눠 칸 좌표로 바꾸고, 칸이 바뀌면 알린다 | 콜라이더가 없다. 4-A 의 `RoomLayout` 을 그대로 쓴다. 변환이 순수 계산이라 EditMode 테스트가 된다. 매 프레임 계산한다 |

**문턱에서 앞뒤로 오가면 알림이 여러 번 온다.** 어느 안이든 이 경우를 어떻게 다룰지 함께 정한다.

### 3. 방을 옮길 때의 카메라

| 안 | 모양 | 따져 볼 것 |
|---|---|---|
| 가 | 카메라 하나. 방에 들어가면 `Confiner2D` 의 경계를 새 방으로 바꾼다 | 오브젝트가 적다. 경계를 바꾸는 순간 카메라가 튈 수 있다 |
| 나 | 방마다 `CinemachineCamera` 를 두고, 들어간 방의 카메라 우선순위를 올린다. `CinemachineBrain` 이 블렌드한다 | Cinemachine 이 권하는 사용법이다. 블렌드가 공짜다. 카메라가 여덟 개다 |

**Cinemachine 3 는 2 와 이름이 다르다.** 인터넷 자료 대부분이 2 기준이다(`CinemachineVirtualCamera` 는 3 에서 `CinemachineCamera`).
설치된 버전을 먼저 확인하고 그 버전의 문서를 본다.

### 4. 칸 좌표를 월드 위치로 바꾸는 곳

4-A 의 `RoomCell` 주석이 '월드 좌표로 바꾸는 곳은 한 곳만 둔다' 고 약속했다. 방을 놓는 코드, 방 찾기(정할 것 2 의 나), 카메라 경계가 모두 쓴다.
`Logic` 에 순수 계산으로 둘지, 방을 놓는 컴포넌트에 둘지 정한다.

### 5. 방 안 장애물과 BFS

**방을 놓고 걸어 본 뒤 판단한다.** 넓은 방이 비어 보이면 방 안에 장애물을 무작위로 놓고, 들어온 문에서 나가는 문까지
길이 막히지 않았는지 BFS 로 확인하는 것을 넣는다. 넣기로 하면 계단을 더하거나 명세를 나눈다.
넣지 않기로 하면 그 이유를 적는다. [한 줄 걷기 결정](../decisions/room-layout-linear-walk.md)의 한계 절이 이 판단을 기다린다.

### 6. 시드의 출처

판마다 무작위 시드를 무엇으로 만들지(`System.Environment.TickCount`, 시드 없는 `System.Random`, `UnityEngine.Random`) 정한다.
시드를 만드는 데만 쓰고 배치 생성은 4-A 의 시드 난수가 한다.

## 경계: 이 기능이 하지 않는 것

- **문 잠금과 열림, 웨이브, 방 클리어, 보상** → 4-C. 4-B 의 문은 늘 열려 있다.
- **가방 여는 시점** → 4-C.
- **복도** → 하지 않는다. 문을 지나면 바로 옆방이다.
- **방 전환 연출** (페이드, 화면 가림) → 하지 않는다. 카메라 블렌드가 있다면 그것뿐이다.
- **보스 방 전용 모양, 보스** → 5번.
- **미니맵** → 하지 않는다 (4-A 경계).
- **방 불러오기와 내리기, 보이지 않는 방 끄기** → 하지 않는다. 방 8개는 한 씬에 늘 있다. 성능 문제가 보이면 측정한 뒤 판단한다.
- **모양이 다른 방 프리팹 여러 개** → 정할 것 5 의 판단 뒤에 정한다.
- **카메라 흔들림** → Phase 5. 도구만 이번에 들어온다.

방 경계에서 반올림이 어느 쪽으로 가는지가 틀리기 쉬운 곳이다. 떨어지지 않으면 해당 없음과 이유를 적는다.

## 메모

**지금 씬의 방은 좌우 벽 둘뿐이다.** `[Level]` 아래 `Wall` 과 `Wall (1)` 이 x = -8.9 와 8.65 에 높이 10 으로 서 있고 위아래 벽이 없다.
방 프리팹이 들어오면 이 둘을 대신한다.

**계단 1 결과: 방 프리팹 `Prefabs/Rooms/Room.prefab` 하나를 만들었다.** 바깥 32 × 18, 문 폭 4, 중심이 원점이다.
벽은 Tilemap 한 장(`Tile_Wall`)에 80 칸을 칠했고, 바닥은 스프라이트 한 장을 늘렸으며, 문 넷은 닫힌(켜진) 상태로 저장했다.
**방 크기는 짝수로 정했다.** Tilemap 의 칸 (x, y) 는 x 에서 x+1 까지를 덮어, 홀수 폭이면 방 중심이 반 칸 어긋나고 Grid 를 반 칸 옮기는 요령이 필요하다.
짝수면 -16 부터 15 까지 칠해 -16 에서 16 까지 덮는다. 문도 짝수 폭(4)이라 가운데에 맞는다. 크기가 적당한지는 계단 4 에서 카메라가 붙은 뒤 다시 본다.

**벽 콜라이더는 Outlines 다. 처음 권한 Polygons 가 대각선으로 벽에 붙어 움직일 때 걸리는 버그를 만들었다.**
Polygons 는 합친 벽을 볼록한 조각 여러 개로 다시 잘라, 사각형 몸이 조각 사이 이음매의 꼭짓점에 걸린다(Box2D 의 ghost collision).
Outlines 는 이어진 선(체인)이라 이웃 선분을 알고 있어 걸리지 않는다. Polygons 를 고른 이유는 '벽 안이 비어 빠른 물체가 파고들면 밀려나지 않는다' 였는데,
플레이어가 이미 Continuous 충돌 감지라 우리에게 해당하지 않았다. 마찰(재질 없음, 기본 0.4)도 후보였지만 하나씩 바꿔 보니 Outlines 만으로 걸림이 사라져 마찰은 건드리지 않았다.

**Tilemap 메뉴는 우클릭한 오브젝트를 부모로 쓰지 않는다.** 선택한 것이 `Grid` 가 아니면 씬 루트에 새 `Grid` 를 만든다. 끌어다 `Room` 아래로 옮기고 위치를 0 으로 확인했다.

**계단 2 결과: `LevelBuilder` 가 `Awake` 에서 시드로 배치를 만들고 방 여덟 개를 놓는다.** 방 크기는 `Room.Size` 가
벽 Tilemap 의 칠한 범위(`cellBounds`)에서 읽어 32 와 18 이 코드 어디에도 없다. 범위는 타일을 지워도 줄지 않아, 벽을 다시 칠하면
`Compress Tilemap Bounds` 를 실행한다. 홀수로 읽히면 `Debug.Assert` 가 알린다. 늘어난 짝수 범위는 잡지 못해 '문과 문 사이에 틈이 없다' 를 눈으로 본다.
칸 좌표를 월드 위치로 바꾸는 곳은 `LevelBuilder.ToWorld` 한 곳이다(정할 것 4). 곱셈 한 줄이라 `Logic` 으로 떼지 않았고,
계단 3 에서 되돌리는 계산이 생기면 함께 옮긴다. 시작 방이 늘 칸 (0, 0) 이라 플레이어를 옮기는 코드가 없다.
시드는 `UnityEngine.Random.Range` 로 하나만 뽑는다(정할 것 6). 배치는 4-A 의 `System.Random(seed)` 가 만들어 다른 코드가 뽑는 것과 섞이지 않는다.
씬에서 손으로 놓은 적 넷, 옛 벽 둘, 확인용 방 하나를 지웠다.

**'막이' 를 '문' 으로 바꿨다.** 문 오브젝트가 켜져 있으면 닫힌 문이다. 메서드도 `SetDoor(side, hasDoor)` 에서 `SetDoorOpen(side, isOpen)` 으로 바꿨다.
옛 이름은 통로가 있다는 뜻의 '문' 과 길을 막는 문짝이 한 단어에 섞여, 여는 쪽이 켜는 것인지 끄는 것인지 헷갈렸다.

**계단 3 결과: `RoomTracker` 가 매 프레임 플레이어 위치를 칸으로 바꾸고, 칸이 바뀌면 `OnRoomEntered(Room)` 을 알린다(정할 것 2 의 나).**
트리거 콜라이더(가)는 버렸다. **우리 투사체는 트리거에 무엇이든 닿으면 사라져**, 방을 덮는 트리거를 두면 화살이 쏘자마자 사라진다.
막으려면 전용 레이어와 충돌 매트릭스 변경이 필요했다. 위치를 칸으로 바꾸는 쪽은 콜라이더가 없고 순수 계산이라 테스트가 된다(엔터 더 건전이 칸마다 방을 적어 두고 위치로 찾는 방식).
계산은 `Logic/Rooms/RoomSpace` 로 모았다. 계단 2 의 `ToWorld` 도 여기로 옮겨 칸과 월드 사이의 변환이 한 곳에 있다.

**경계는 `Math.Floor(x / 폭 + 0.5)` 로 늘 양의 방향 방에 붙인다.** `Mathf.RoundToInt` 는 은행가 반올림이라 0.5 는 0 으로, 1.5 는 2 로 가
경계마다 붙는 쪽이 다르다. `(int)` 로 자르면 0 쪽으로 잘려 음수 칸에서 틀린다. `RoomSpaceTests` 20 개가 경계, 음수, 가로와 세로 바뀜, 되돌리기를 겨냥한다(전체 131 개).
`Math.Floor` 는 `double` 을 돌려줘 `(int)` 가 필요하다. 채울 때 한 번 빠졌다.

**`Start` 에서 시작 방에 들어간 것도 알린다.** 구독은 `OnEnable` 에서 하고, 씬이 열릴 때 모든 `OnEnable` 이 어떤 `Start` 보다 먼저라 첫 알림을 놓치지 않는다.
`Awake` 가 아닌 이유는 `LevelBuilder.Awake` 가 방을 놓은 뒤라야 배치를 읽을 수 있어서다.
임시 클리어는 `ResultPanel` 이 보스 방 입장을 듣고 띄운다. 결과 패널이 게임을 멈춰 한 번만 뜬다.

**계단 4 결과: 방마다 가상 카메라(`CinemachineCamera`)를 두고, 들어간 방의 카메라만 켠다(정할 것 3 의 나).** Cinemachine 3.1.7 이다.
실제 카메라는 지금처럼 한 대이고 `CinemachineBrain` 이 켜진 가상 카메라를 따라 움직이며 둘 사이를 0.5 초 블렌드한다.
'실제 카메라 한 대, 가상 카메라 여러 대' 가 Cinemachine 의 기본 설계이고, 구역마다 카메라를 두는 것은 할로우 나이트의 카메라 잠금 영역,
셀레스트의 방 단위 카메라와 같은 모양이다. 카메라 하나의 경계만 바꾸는 안(가)은 경계가 바뀌는 순간 화면이 튄다.

**경계 콜라이더는 꺼 둔다. 패키지 소스로 확인했다.** `CinemachineConfiner2D` 는 `BoxCollider2D` 의 `size` 와 `transform` 만 읽고 `enabled` 를 보지 않는다.
켜 두면 방을 덮는 콜라이더에 투사체가 닿아 사라진다. 레이어와 충돌 매트릭스를 바꾸지 않았다.
끈 가상 카메라도 파괴되지 않았으면 블렌드의 출발점이 된다(`IsValid` 는 파괴 여부만 본다). 우선순위가 같으면 가장 최근에 켠 카메라가 이긴다.
그래서 프리팹의 가상 카메라는 꺼진 채 저장한다. 켜진 채면 가장 나중에 복제된 보스 방 카메라가 화면을 차지한다.

**카메라 경계 크기는 `Room.Awake` 가 벽 범위(`Size`)로 넣는다.** 방 크기는 여전히 벽 타일 한 곳에만 있다. 따라갈 대상(플레이어)은 프리팹이 씬을 가리킬 수 없어
`RoomCameraSwitcher` 가 켤 때 넣는다. 문턱에서 앞뒤로 오가도 떨리지 않아 `Hysteresis` 는 넣지 않았다. 실제 화면(크기 5)에서도 32 × 18 이 적당했다(정할 것 1 확정).

**계단 5 판단: 방 안 장애물은 넣지 않는다(정할 것 5).** 방이 비어 보이는지는 적이 있어야 제대로 볼 수 있어 4-C 에서 웨이브가 방을 채운 뒤 다시 본다.
**장애물을 넣는 비용은 적 AI 에 있었다.** 적은 길찾기 없이 플레이어를 향해 곧장 움직여, 기둥 뒤의 플레이어를 쫓다 붙은 채 멈춘다.
벽에 붙은 작은 장애물만 두는 안은 지형이 달라지는 효과도 작다. 넣는다면 **플레이어에서 시작하는 BFS 로 칸마다 거리를 구해 적이 거리가 줄어드는 쪽으로 걷게 하는
흐름장(flow field)** 까지 가야 의미가 있다. 이러면 BFS 가 길 막힘 확인과 적 길찾기 두 곳에서 일한다. 적 AI(FSM)를 다시 여는 일이라 명세를 따로 두고,
기능 후보 풀에 올렸다. 4-A 가 한계로 넘긴 'BFS 를 실패할 수 있는 자리로 옮긴다' 는 여기서 다시 한 번 미뤄졌다.

**Cinemachine 은 Unity 공식 패키지라 README 출처 표에 적지 않는다.** Input System, TextMesh Pro 와 같은 대우다.
출처 표는 직접 만들지 않은 아트, 사운드, 폰트를 적는 곳이다.
